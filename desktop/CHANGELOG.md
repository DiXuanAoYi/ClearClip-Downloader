# 更新记录

版本号与 `tauri.conf.json` 一致；每个版本对应一个 `desktop-v<版本>` 的 Release。

## 0.5.2

这一版是新仓库的第一个版本（项目原在 `DiXuanAoYi/ClearClip`，已迁到这里），修了几处问题。已装 0.5.1 或更早版本的用户请升级到这一版；项目协议为 MIT，见仓库里的 LICENSE。

**修复**
- **剪辑导入字幕**：除 UTF-8 外，现在也能读 UTF-16 和 GBK 编码的字幕文件（国内常见），以前会提示“不是 UTF-8 编码”
- **剪辑导入字幕**：ASS 里的矢量绘图和特效指令（`{\p1}…`）不再被当成文字导入
- **预览小文件**：缓存有了 2 GB 上限，超过后自动删最久没用的，不再一直占磁盘
- 仓库不再包含最初的 PHP 网页和接口代码，改用 MIT 许可证，第三方许可见 `THIRD_PARTY_NOTICES.md`

## 0.5.1

这一版给剪辑加了四样东西：导入字幕文件、HDR 素材一键转普通画面、播不出来的素材生成预览小文件、叠加素材的入场 / 出场动画；同时把剪辑界面的自动化测试放进了仓库和持续集成。

**新增**（[说明](../docs/video-edit.md)）
- **导入字幕**：“添加素材 → 导入字幕文件”读取 SRT / VTT / ASS / SSA（UTF-8），每条字幕变成一条文字（靠下、带描边），可逐条改内容、时间和样式，撤回一次整批去掉。ASS 只取文字和时间，不保留它的样式和特效。文字条数上限从 100 提高到 500
- **HDR 一键转换**：选中 HDR 的片段或叠加素材，检查器里的提示带“转成普通画面并替换”：用视频规整的“通用兼容”预设只做 HDR → SDR（尺寸、帧率、声音不动），转完把工程里用到它的地方换成转换后的文件，可撤回
- **预览小文件**：实时画面里系统播放器解不了的素材（部分 H.265、ProRes 等），提示旁新增“生成预览用的小文件”，转成最高 540 像素的 H.264 后实时画面改用它；只用于监视器，导出仍然用原素材
- **叠加素材动画**：检查器里的“入场动画 / 出场动画”：从上下左右滑进 / 滑出画面，或缩放；时长 0.1–3 秒，最长不超过素材的一半。实时画面和导出一致

**开发**
- 剪辑界面的浏览器测试（Playwright + Chromium，模拟后端）和纯函数单元测试进了仓库（`npm test`，说明见 `desktop/e2e/README.md`），`desktop-ci` 每次提交都会运行

**注意**
- 新功能在 Linux 上用 Chromium 加模拟后端做过界面测试，滤镜表达式用真实 ffmpeg 渲染验证过；没有在 Windows / macOS 的真实窗口里操作过
- 字幕文件不是 UTF-8 编码时会提示先另存为 UTF-8

## 0.5.0

这一版把剪辑页面整理了一遍（合并入口、新增一批常用的剪辑操作），下载队列改为显示按“文件命名”生成的文件名，并修复了精简版 ffmpeg 下的两个问题。项目后来迁到了新仓库 `github.com/DiXuanAoYi/ClearClip-Downloader`；应用内的更新检查、文档链接已指向新地址。

**改进**
- 下载队列、任务详情、完成 / 失败通知、本地 API（新增 `fileName` 字段）、命令行 `list` 和网页控制台里显示的名字，现在都是按“设置 → 下载 → 保存 → 文件命名”生成的**文件名**（同时处理了重名），不再是作品标题；鼠标停在队列里的名字上能看到作品标题。识别到链接后自动下载的提示也用同一个文件名，手动下载、识别后自动下载、手机发送三条路径的命名完全一致
- 文件命名模板新增 `{quality}`（清晰度，如 `1080P`）：同一个作品下载多个清晰度时，各自得到不同的文件名。设置里有变量按钮和实时示例，写了不认识的变量（比如拼错）会提示它会原样写进文件名
- **剪辑页面整理**（[说明](../docs/video-edit.md)）：
  - 工具栏收拢：六个“添加”按钮合并成一个“添加素材”（点按钮是添加到主轨，小箭头里是叠加素材、配乐和从媒体库添加）；“打开…”右边的小箭头列出最近的工程（最多 8 个）；删掉了和 `Home` 重复的“回到开头”，把“精确预览”并入监视器下的“实时画面 / 精确预览”切换，没有素材时不再显示预览状态条；检查器里重复的“近似”提示删掉了
  - 新增：监视器下的 `«` `‹` `›` `»` 逐帧前后移动、跳到上一个 / 下一个剪辑点（`,` `.` `[` `]`）；时间线上方的一排操作：向左 / 向右裁剪（`Q` / `W`，一步去掉红线一侧）、分离音频（把片段的声音放到配乐轨并静音画面）、复制（`Ctrl+D`）、波纹删除（`Shift+Delete`，后面的叠加素材、文字、配乐一起前移）；“应用到全部片段”（调色 / 画面方向）、“应用到所有衔接处”和“去掉所有转场”；吸附开关（会记住）；`Ctrl+滚轮`缩放时间线；“快捷键”说明面板
  - 以上每一项撤回一次就还原

**修复**
- 精简版 ffmpeg（没有 `boxblur`）下，工具箱“竖转横”的“模糊背景”会失败；现在和视频规整、剪辑一样，没有 `boxblur` 时改用 `gblur`
- 精简版 ffmpeg 没有 `cropdetect`（GPL 滤镜）：视频规整的“去黑边”以前检测不到黑边就悄悄不生效，预览对比和任务说明里什么也不写；现在“设置 → 组件”的限制清单、“去黑边”开关旁边、预览对比和任务说明里都会写明“没有 cropdetect，已跳过去黑边”。完整版不受影响

**注意**
- 剪辑页面的新操作只在 Linux 上用 Chromium 加模拟后端做过界面测试，没有在 Windows / macOS 的真实窗口里操作过；精简版 ffmpeg 的两处修复在 Linux 上用 BtbN 的精简版（N-127252）跑过真实 ffmpeg 测试
- 分离音频不支持变速的主轨片段和循环的叠加素材（配乐没有变速功能），会提示原因

## 0.4.0

这一版新增了整栏的**剪辑**（时间线剪辑、叠加多条素材、实时预览、动态区域感知），以及视频规整、LUT 工作室、调试包的多项更新，所以版本号从 0.3.x 提到 0.4.0。

**新增**
- 视频规整：分段色彩匹配。混剪、多来源拼接的视频里，各个镜头偏色、亮度、对比度、饱和度不一致时，找出和整体不一致的镜头，只把它们单独校正到和整体一致，一致的镜头原样不动（[说明](../docs/video-normalize.md)）。详细设置里可调强度，“检测第一个文件的色彩差异”能先看时间轴和每个镜头的问题，可以取消不想校正的镜头，并能看校正前后的对比；新增“混剪 / 多来源拼接”预设
- LUT 工作室（工具箱新标签，[说明](../docs/lut-studio.md)）：用一张示例图片（或视频里的一帧）边看边调，生成新的 `.cube` 3D LUT。基础调色有曝光、黑场 / 白场、中间调、对比度、阴影 / 高光、色温 / 色调、饱和度、自然饱和度、色相、分色调、整体强度，附七个一键风格；可以先叠加别人的 `.cube` 作为基底再调整；也可以选一张参考图，让示例图片的明暗分布和整体色彩向它靠拢。预览和 ffmpeg 的 `lut3d` 用同样的四面体插值，看到的就是文件的真实效果；可保存 17 / 33 / 65 格点的 `.cube`，把同样的效果导出成 png / jpg / webp 图片，或一键带到视频规整里使用
- 调试版现在使用独立的程序标识（`com.dixuanaoyi.clearclip.debug`，产品名 ClearClip Debug），和已安装的清影互不干扰，不会再被已经开着的正式版挡住；窗口标题和侧栏左下角显示版本号和提交号，一眼能确认运行的是哪一次构建
- 调试版流水线 `desktop-debug`：往 `claude/**`、`debug/**` 分支推送且提交说明带 `[debug-build]`，或在 Actions 里手动运行，就会构建 Windows 便携调试包（带控制台窗口和开发者工具），上传成 Actions 产物，不用合并、不用发版（[说明](../docs/debug-build.md)）

- 视频规整：新增**输出电平**——16–235（电视范围，默认，游戏、影视美术、投稿平台等的常见要求）/ 0–255（全范围）/ 沿用素材。全范围的素材选 16–235 会压回电视范围；电视范围的素材选 0–255 会拉开，输出文件里写明对应的范围标记。色阶、LUT、HDR 转 SDR 都先在电视范围里做完，最后一步才拉开。以前“补全色彩信息”里附带的“全范围转电视范围”现在由这个选项控制（默认行为不变）
- 视频规整：新增**降噪**（关闭 / 弱 / 中 / 强 / 高质量）。弱 / 中 / 强用 `fftdnoiz`（精简版和完整版 ffmpeg 都有），高质量用 `nlmeans`（画质最好、速度约为四分之一）；缺滤镜时依次退到 `hqdn3d`、`atadenoise` 并提示。降噪放在缩放之前（缩小时放在之后）和色阶、LUT 之前；预览会先预热半秒再截图，和实际处理一致。[说明里有“噪点多怎么办”的建议](../docs/video-normalize.md)
- 视频规整：分段色彩匹配可以**按镜头单独调节**：检测出的不一致镜头各有一个“单独调节”开关，打开后这个镜头用自己的自动校正强度和亮度 / 对比度 / 饱和度 / 色温 / 色调；没有单独调节的镜头都用**统一调节**（同样五项）。取代了原来的“取消勾选就不校正”（把单独调节里的自动校正强度拉到 0 即可达到同样的效果）
- 视频规整：分段色彩匹配可以在检测之前**预先设置排除的时间段**：按时间（`0:03 – 0:06`，结束留空 = 到结尾）或按帧号（第几帧到第几帧，从 1 开始、含首尾）填写。排除的时间不计入“整体”的基准、不被标成不一致，自动校正、单独调节和统一调节都绕开它，保持原样；一个镜头只有一部分被排除时，其余部分照常校正。时间轴上用斜线标出排除的段，不一致的镜头可以一键“排除这个镜头”，改了排除的时间会自动重新检测（不重新解码整个文件）。默认只对第一个文件生效，可以勾选对所有文件生效。这里的“帧区域”按“第几帧到第几帧”理解，不是画面里的某块区域
- **剪辑**（工具箱新标签，[说明](../docs/video-edit.md)）：时间线剪辑。把多段视频 / 图片按顺序排在时间线上，拖动片段边缘或填入点 / 出点来裁剪，`S` 分割，拖动调整顺序；每个片段可调速度（0.25×–4×）、音量、静音、淡入淡出、画面方向（旋转 / 翻转）、亮度 / 对比度 / 饱和度；片段之间可加 16 种转场（淡入淡出、闪黑、闪白、溶解、擦除、滑动、圆形、时钟、马赛克）；加文字（时间、位置、字号、颜色、描边、底色块、字体，可直接在监视器里拖动）和配乐（开始时间、裁剪、音量、淡入淡出、循环、片段里有人声时自动压低）；输出尺寸（含竖屏、方形）、帧率、画面适配（留黑边 / 铺满裁切 / 模糊背景）、画质、H.264 / H.265、MP4 / MKV 可选。监视器是**实时画面**：转场、叠加、文字、调色、配乐直接合成在里面，改完参数马上能看到，不用先“生成预览”；要逐帧核对再点“生成精确预览”，用和导出同一套流程渲染一份低分辨率的成片；撤回 / 重做、保存成 `.ccedit` 工程文件、素材找不到时标红并可重新指定、草稿自动保存。媒体库里的视频详情新增“放进剪辑…”
- **动态区域感知**（剪辑里选中视频片段后的“区域”标签，[说明](../docs/video-edit.md)）：在一个镜头里框出一个物体（点程序感知到的运动物体，或自己拖一个框），程序在整个片段里持续追踪它的位置，再把效果绑在这条轨迹上：马赛克 / 模糊（遮走动的人脸、车牌）、局部调色（可以改成“作用于区域以外”）、跟随聚焦（放大并跟着物体走，也可以按成片的比例把横屏素材裁成竖屏）。形状（方形 / 椭圆）、边缘羽化、范围扩大、生效时间可调；追偏了就把红线移到那一刻、在监视器里把框拖回物体上，留下一个不会被重新追踪改掉的“手动点”，再从这一帧重新追踪；追踪不到的位置会标出来，并能一键跳过去。位置按占画面的比例、时间按素材自己的时间保存，分割、裁剪、变速、旋转、翻转之后仍然对得上；一个片段最多 8 个区域。导出前先在本机按轨迹逐帧生成遮罩，再由 ffmpeg 合成，所以形状、羽化、“作用于区域以外”都准确
- **剪辑：叠加素材（画中画、贴纸、水印、GIF）**：主轨上面可以叠加多条视频 / 图片 / GIF，放在任意时间、任意一条叠加轨（最多 8 条、100 个素材）上，不再只能排在末尾的一行。素材不够用一条轨道时同时出现多条；位置、大小、旋转、翻转、不透明度、淡入淡出、速度、音量、亮度对比度饱和度都能单独调，选中后可以直接在监视器里拖动、缩放、旋转；GIF 默认循环并静音。可以把主轨上的片段“移到叠加轨”，叠加素材也能“移到主轨”。文字画在所有叠加素材之上，叠加素材不会把成片拉长（[说明](../docs/video-edit.md)）
- **剪辑：把文件直接拖到时间线**：从资源管理器 / 访达拖文件，落在哪一行就放进哪一行（叠加轨从落点的时间开始，主轨按落点插入，音频行当配乐），拖动时高亮落点；一次选多个文件时，它们在同一条轨上依次排开，轨道被占了自动换到最近的空轨
- **剪辑：实时预览**：监视器直接合成主轨、叠加素材、转场、文字、调色、淡入淡出、音量、区域效果和跟随聚焦，不用每次点“生成预览”再等渲染。它是近似效果，“精确预览”（原来的“预览成片”）保留为可选项，需要逐帧核对时再生成
- **剪辑：支持更多素材格式**：视频增加 3G2、MTS / M2TS、OGV、VOB、F4V、ASF、DIVX、MXF，图片增加 JFIF、TIFF、AVIF、HEIF，音频增加 AIFF、AC3、MKA、AMR，加上原有格式（含 GIF、WebP、BMP、HEIC）；文件对话框、拖放、媒体库的素材都按同一份清单识别。能不能读最终由 ffmpeg 决定，读不出来的（比如没有解码器的 AVIF / HEIC）会明确提示，建议先转成 PNG / JPG
- 滤镜图很长（分段色彩匹配的镜头很多）时写进临时文件交给 ffmpeg（新版 `-/filter_complex`，旧版 `-filter_complex_script`），避免超出 Windows 命令行约 32K 字符的上限

**修复**
- 视频规整：全范围的 `yuvj420p` 素材选 0–255 输出时，格式转换会把它悄悄压成电视范围；现在转换前明确写成“范围不变”
- 视频规整：“放进目标框并用模糊背景补边”（竖转横 / 横转竖的模糊背景）在精简版（LGPL）ffmpeg 里会失败——这类 ffmpeg 没有 `boxblur`（它是 GPL 滤镜）；现在没有 `boxblur` 时改用 `gblur`，模糊程度接近。这个问题在 0.3.0 / 0.3.1 里就有，是做剪辑的“模糊背景”时用精简版实测发现的

**注意**
- 分段色彩匹配用统计的办法判断“整体”，画面内容本来就不同色调的镜头可能被误判，所以只处理偏离超出正常范围的，强度可调，可以逐个单独调节；HDR 素材暂不支持
- 降噪的参数是用加了随机噪点的合成画面标定的，没有在真实的夜景 / 高 ISO 素材上逐档调过，实际效果请先用“预览对比”看；新的输出电平、降噪和单独调节只在 Linux 上用真实 ffmpeg 测过（系统自带的 6.1 和 BtbN 的 N-127252 两个版本），没有在 Windows / macOS 上跑过
- 剪辑的实时画面是近似预览：转场的形状是对着 ffmpeg 的输出量出来的近似（溶解、马赛克用淡入淡出代替），调色、字体、淡入淡出也是近似，配乐的压低听不出来，高于 100% 的音量按 100% 播放，“模糊背景”显示成留黑边，以“精确预览”和导出的成片为准；实时画面能不能播某个素材取决于系统 WebView 的解码能力，播不出来的会提示并用静态画面代替，导出不受影响。叠加素材的位置、大小等是固定值，没有关键帧，也没有波形；叠加素材不能加转场和区域；HDR 素材不做 SDR 转换（先用视频规整）。剪辑只在 Linux 上用真实 ffmpeg 6.1 做过导出测试，界面用 Chromium 加模拟后端测过，**没有在 Windows / macOS 的真实窗口里操作过**；导出用系统自带的 6.1（完整版）和 BtbN 的 N-127252（精简版，没有 libx264，用 libopenh264 编码）各跑了一遍全部真实 ffmpeg 测试（包括叠加素材的导出）；实时画面只在 Chromium 里测过，Windows（WebView2）和 macOS（WKWebView）上的视频解码、CSS 滤镜和遮罩细节可能与此略有不同
- 动态区域感知用的是传统图像算法（帧差找运动物体、模板匹配做追踪），不是 AI 识别：不认识人脸 / 人 / 车，看不见静止不动的物体，镜头大幅移动或变焦时感知不出单独的物体；追踪在物体被长时间挡住、形状变化很大、框里几乎是纯色、运动模糊严重时会丢，框的大小追踪时是固定的，物体明显变大变小要靠手动点和调整大小校正。实时画面里区域效果只是示意（不显示羽化和“作用于区域以外”，跟随聚焦没有算镜头平滑），以“精确预览”和导出为准。视频规整的分段色彩匹配还不能排除画面里的某块区域。算法用合成画面（带纹理的移动物体，加平移、遮挡、噪点）和真实 ffmpeg 渲染的合成视频测过，**没有在真实拍摄的素材上逐类调过参数**；导出在 Linux 上用系统 ffmpeg 6.1 和 BtbN 的精简版各跑了全部测试，界面用 Chromium 加模拟后端（追踪结果是模拟的）测过，没有在 Windows / macOS 的真实窗口里操作过
- 手动调节（亮度、对比度、饱和度、色温、色调）是 YUV 里的近似，不等同于专业调色软件的色彩科学

## 0.3.1

**修复**
- 视频规整：装了较新的 ffmpeg（2026 年的开发版，例如 BtbN 的 master 完整版）后，设置 → 组件和规整面板里把 zscale、vidstab、lut3d、normalize 等滤镜全部报告成“没有”。原因是新版 `ffmpeg -filters` 的标志列从 3 个字符变成了 2 个，旧的解析认不出任何一行。现在两种格式都认，并且按“带输入输出类型”识别行，格式再变也不容易失效
- 视频规整：新版 ffmpeg 不再用 `-color_primaries` / `-color_trc` 给编码输出写色彩标记，不经过滤镜时写出来的色彩信息会缺项；现在统一用 `setparams` 写入。已用 BtbN 的 N-127252 版和系统自带的 6.1 版把全部真实 ffmpeg 测试各跑了一遍
- 已经是完整版 ffmpeg 时，不再提示“去设置 → 组件安装完整版”
- Windows：迷你窗、悬浮拖拽窗仍然会带着原生标题栏、空白地出现在屏幕左上角。0.2.1 的做法是在显示窗口之后再去掉标题栏样式，但“显示”是排队到界面线程执行的，去样式先于窗口库自己的样式更新，随后又被写回来；预先建好的隐藏窗口也有自己冒出来、点不动的情况。现在这两个小窗不再写在配置里预先建好，而是用到时才创建（一创建就在右下角、定好大小、无边框、置顶），不用了就销毁；Windows 上还给窗口挂了样式守卫，任何时候有人写窗口样式，标题栏相关的位都会被去掉。程序启动后不再有任何隐藏着的小窗

## 0.3.0

**新增：视频规整**（[说明](../docs/video-normalize.md)）
- 工具箱新增“视频规整”：把手机录屏、直播录制、平台下载的成片统一成同一规格。选好文件后按检测结果（可变帧率、HDR、色彩标记、黑边、响度……）自动推荐预设，预设有通用兼容、剪辑素材统一、手机录屏、直播录制、平台下载成片、竖屏短视频、横屏 1080p、省空间（HEVC）；可批量，已符合规格的文件不重新编码
- 可单独调：画面尺寸（缩小 / 补黑边 / 模糊背景补边 / 铺满裁切）、帧率（可变帧率转标准固定帧率）、HDR 转 SDR、色彩标记补全与修正、自动色阶、`.cube` LUT（可调强度）、自动去黑边、采样率 / 声道 / 响度、音画不同步与时间戳修正、编码与质量；预览区抽一帧对比处理前后
- 防抖：vidstab 两遍防抖，没有 vidstab 时退回 deshake
- 可接进自动规则（下载完成后自动规整）和直播录制（录完自动规整）；媒体库多选或单个条目详情里都能直接送去规整
- 设置 → 组件：显示 ffmpeg 的版本、精简 / 完整版本、HDR 转换 / LUT / 防抖 / 硬件编码的可用情况；可以切换到完整版（GPL，带 x264、x265、vidstab、zscale，由用户主动下载，不随清影分发）；macOS 请用 Homebrew 安装
- 精简版 ffmpeg 下的兜底：没有 x264 时优先用试编码通过的硬件编码器（NVENC / QuickSync / AMF / VideoToolbox），再退到 openh264；没有 zscale 时用程序内置的 3D LUT 做 HDR → SDR；没有 vidstab 时用 deshake

**注意**
- 硬件编码器没有在真实设备上测过；完整版 ffmpeg 的下载流程只在本地用现成的 ffmpeg 验证了检测和使用，没有走过完整的下载安装
- 内置 LUT 的 HDR → SDR 与 zscale 的结果接近但不完全一样

**媒体库与整理**（[说明](../docs/library-and-tools.md)）
- 标签、收藏、评分、备注；导入已有文件夹；磁盘统计；回收站；按规则整理文件夹
