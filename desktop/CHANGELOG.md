# 更新记录

版本号与 `tauri.conf.json` 一致；每个版本对应一个 `desktop-v<版本>` 的 Release。

## 1.8.1（扩展 1.19.0）

### 屏幕翻译

- 【停不下来】在悬浮窗和主程序里先后点了开始（或按了快捷键）后，屏幕翻译就关不掉了：主程序的“停止”、快捷键、悬浮窗都没用，译文过一会儿又自己出来。原因是重新开始时，旧的那次翻译在退出时把“当前在跑的是哪一次”清空了，新的那次从此没人管，一直在后台识字、贴译文。现在旧的那次只收拾自己；停止之后还在路上的那一轮识字 / 翻译也不再贴译文。系统声音字幕有同样的问题，一起修了。
- 【按钮统一】悬浮窗里的“开始 / 停止”和主程序“屏幕翻译”页的按钮现在是同一套：停止就是停止（以前悬浮窗用的是“切换”，状态没跟上时会变成又开始一次）；开始用上次的区域，没有就去框选。悬浮窗按钮上标了快捷键。
- 【增强识字的排版】选“增强识字组件”时，译文字号太大、位置偏、上下相邻的几项被并成一大段（中英混杂地翻）。原因是这个识字组件为了认得准，把每个文字框向外扩了一大圈（约 1.6 倍），排版时又直接用了这个框，字高被算成实际的两三倍。现在识字仍用扩过的框，排版用收紧到字迹的框，和 Windows 自带识字一致；截图翻译、文件翻译的增强识字也一样受益。
- 【列表不再并成一段】菜单、侧栏、列表这种一行一项的短文字，以前行距近一点就会被当成一段话一起翻（结果半中半英）。现在只有上一行是写满了才换行的长句、或者挨得非常紧（多行按钮 / 标题）才并成一段。
- 【图标被认成汉字】银行卡、窗口、网格之类的方框图标常被认成“日”“口”“田”，1.8.0 的图标过滤只认符号和字母。现在单独的“口 / 田 / 回”方块字、以及跟在外文前面的“日 / 口 / 目……”（如“日 Billing”“口 Desktop app”）都当成图标去掉；中文里的“日”不受影响。
- 【视觉模型识字】标准模式选“视觉模型”识字时，以前用的是漫画的提示词（找对话气泡、会跳过界面文字），现在用专门给软件界面的提示词：每个菜单项、按钮、列表项各是一块，图标不算文字。

### AI 术语库

- 【文件夹】术语库可以放进多层文件夹（如“游戏 / 原神”）：列表按文件夹分层显示、可以折叠；可以新建文件夹 / 子文件夹（用 / 一次建多层）、重命名或移动（连同里面的术语库和子文件夹）、删除（里面的术语库往上挪一层，不会被删）；编辑术语库时可以选或直接输入文件夹。内置的软件界面术语、给某个软件建的术语库放在“软件界面”文件夹里。
- 【添加一行】插在当前选中（点过或正在输入）的那一行下面，没有选中的行就加在最下面（以前总是加在最上面）；新行自动选中、光标放进去。术语超过 300 条时可以翻页，新加的行总在显示范围里。

## 1.8.0（扩展 1.19.0）

这一版主要是内部重构（按上次梳理出的问题清单），功能上能感觉到的变化列在前面。

### 屏幕翻译

- 【图标不识别、不翻译】软件界面上的图标（人像、银行卡、齿轮、铃铛、心形……）以前会被识字认成“8”“©”“Q”之类的字，再拿去翻译。现在单独的图标块直接丢掉（一两个字符、不是中日韩文字、框接近正方形，或者全是符号）；“图标 + 文字”被认成一行时（如“8 Account”），按画面里图标和文字之间的大空隙认出行首的图标并去掉，译文框也挪到文字开头。实时翻译、截图翻译的本机识字都生效；“屏幕翻译”里有开关（默认开）。视觉模型的提示词也加了“图标不是文字”。只用合成图片测了，没在真实 Windows 桌面上对比过；两个字母且框是方的短词（不在常见词表里的）可能被误当成图标，觉得漏了可以关掉这个开关。

### 第二轮合并（主程序 + 扩展）

- 【翻译入口】工具箱 → AI 里去掉“翻译字幕”“翻译文件”（和「文件翻译」页是同一个后台任务，但不能预览、改译文、PDF 原处排版、选识字方式），那里改成一行“翻译字幕、文档在 文件翻译 页”；媒体库里字幕的“翻译字幕”也直接把文件交给「文件翻译」页。字幕页签里对单个字幕轨的“翻译”保留。
- 【翻译历史】截图翻译的历史以前在“设置”里看，现在和实时屏幕翻译的历史一起放在「屏幕翻译 → 翻译历史」，可以按“全部 / 实时翻译 / 截图翻译”筛选，截图那条可以“存进摘录”；设置里只留开关。
- 【悬浮窗】桌面上的“悬浮拖拽窗”（拖链接下载）和“屏幕翻译悬浮钮”合成一个清影悬浮窗：拖链接下载照旧，屏幕翻译页里开了“悬浮窗里放屏幕翻译控制”时多一个“译”，点开在旁边展开开始 / 停止、暂停、模式、重选区域、存译图、显示 / 隐藏译文。两个开关任一个开着就显示，悬浮窗上的 × 两个一起关。解锁应用后悬浮窗会按设置恢复（以前屏幕翻译悬浮钮解锁后不会回来）。
- 【摘录统一】以前“摘录”有两套：桌面写作窗的“存入摘录”只能在写作窗里看；浏览器扩展的“摘录选中文字到清影”和各处“存为笔记”其实存成“收到的文件”里的文字便签。现在都存进同一份摘录（记下来源标题和网址），侧栏「生词本」改名「生词与摘录」，里面切到“摘录”就能搜索、按来源筛选、加笔记、打开原网页、导出 Markdown；扩展存进来一条时列表自动刷新。以前扩展存成便签的那些，第一次启动时自动搬进摘录（保留原来的时间，“收到的文件”里对应的那条删掉）；手机发来的普通文字仍在“收到的文件”。摘录单条上限从 2 万字放到 20 万字（视频摘要的整份学习稿也能存）。
- 【扩展弹窗】“发现”页里“从一个页面发送多项”原来有 4 个入口（检测到的内容列表、页面媒体总览、批量选取、本页所有视频链接），收成一个“页面媒体总览 / 批量发送”：弹窗里只显示检测到几个视频流；总览页顶部的视频流列表加了“全部发送”（和以前弹窗里一样按清晰度排序），工具栏加了“在页面上点选…”（以前的批量选取，会切回原网页）和“本页所有视频链接 → 清影”。

### 扩展：悬浮窗合并

- 【视频胶囊】视频上以前最多有 5 个各自定位的小东西：左上角的播放增强工具条和视频摘要的“笔记 (n)”按钮（坐标完全一样，会叠在一起）、右上角的“用清影下载”、右下角的字幕层胶囊和音效按钮（也几乎同一位置）。现在合成一个清影胶囊，放在视频右下角、控制栏上方，鼠标移开 1.5 秒后一起隐藏：胶囊上是“下载”、倍速 ‹ 1× ›、字幕开关、音效状态（各自开着才有），⋮ 菜单里是快进快退、截图、画中画、A–B 循环、播放增强设置、实时音效、字幕设置 / 精听 / 生词本 / 关闭字幕层、记下当前这句、关闭视频摘要，以及没打开时的“视频摘要 / 总结”“双语字幕层”。各功能的设置面板都在胶囊上方打开。各功能的开关和设置不变；默认设置下（只开了实时音效）视频上仍然什么都不显示。音效的“只在鼠标移到视频时显示”选项去掉（胶囊本来就只在鼠标移上去时出现）。
- 【划词翻译合一】划词工具条的“翻译”改为打开网页翻译那张卡片（可对比其他翻译服务、转到翻译窗、存为笔记、复制），不再是另一张只用一个服务的卡片；在 iframe 里划词也在那个框架里打开。
- 【删除】网页翻译的划词“译”小按钮和它的设置项（入口只留划词工具条；右键“翻译选中的文字”和 Alt+D 翻译窗照旧）；视频摘要的“笔记 (n)”按钮和“在视频上显示笔记按钮”设置（按 n 键或胶囊菜单里的“记下当前这句”）。

### 修复

- 【解除限制】“解除网页限制”（允许复制、右键、选中）改成按网站开启，默认不再对所有网站生效；升级上来时会关掉全局开关并提示一次。
- 【录原声】字幕层里录下的原声存到清影桌面端（以前存在浏览器里，10 MB 的存储放不了几段），导出 Anki 时一起打包成 .zip（带 `[sound:]` 引用）。浏览器里以前存的原声会自动搬过去。
- 【文件翻译】任务带上类型和输入：切到别的页面再回来、或重开窗口，文件列表和进度还在，能接着看上次的任务。
- 【备份】备份现在包含生词本（含复习记录）、生词原声、术语库、AI 专家、摘录、翻译记忆和浏览器扩展的笔记 / 高亮；数据库用快照方式备份，不会备份到写了一半的文件。恢复时原来的文件留一份 `.before-restore`。
- 【缓存】AI 结果缓存的版本号改用真实启用的翻译路由，换了模型池里的翻译服务后不会再拿到旧结果。

### 重构

- 【后台任务】清影的后台任务分三条队列：交互（听写、剪辑预览等，最多同时 6 个）/ AI（翻译字幕、摘要、文件翻译、取在线字幕，3 个）/ 重任务（转写、转码等，2 个），转码排队时不再挡住文件翻译。查词、划词这类即时请求本来就不进队列。任务快照带类型、输入和参数。桌面端内部（屏幕翻译等）直接等结果，不再借给扩展用的任务表轮询；扩展里所有 AI 调用改用一个实现（取消、超时、接上旧任务、进度）。
- 【模型池】看图的请求（截图翻译、识图）优先交给能看图的模型，没有就明确提示；机器翻译服务（DeepL、Google、微软）可以设每月字符额度，用完自动跳过，用量在模型池里显示。
- 【设置】后台改设置统一加锁；设置页保存时带上打开时的样子做三方合并，别的窗口或后台在这期间改过的项不会被设置页覆盖；改动会广播给所有窗口。
- 【翻译记忆】新增翻译记忆（`tm.db`）：网页、字幕、屏幕、文件翻译共用“原文 → 译文”，同一句话不重复翻；在文件翻译阅读器里改过的译文记为人工译文，以后优先使用；换了术语库或 AI 专家后旧的机器译文自动不再命中。“设置 → AI 术语库”里能看到条数、清空机器译文。机器翻译服务也遵守术语库（术语先换成占位符，译完再换回来）。
- 【扩展：清影没开时】网页翻译在连不上清影时，改用你自己开着的备用服务（DeepLX / 自定义接口），右下角提示一次；不会自动发给谷歌。
- 【扩展：视频会话】视频摘要面板和字幕层共用同一份字幕和译文：摘要读到的文稿字幕层直接用，不再读一遍；字幕层的译文改为字幕翻译任务（和“翻译文稿”是同一种，走翻译记忆），谁先翻好另一个直接显示；摘要里换了字幕轨、转写完成、站内切换视频，字幕层通过订阅自动跟着换。
- 【扩展：词卡】字幕层的查词浮窗和划词工具条的“释义”共用一张词卡（释义、本句意思、本句、例句、加入生词本），划词释义也有了例句和一键收藏。
- 【识字】图片识字统一入口：截图翻译（桌面截图窗、扩展截图）可以选“本机识字 + 翻译模型”——用屏幕翻译里选的本机方式（增强识字 / Windows 自带 / 识字接口）认字，位置是像素级的，图片不发给大模型，译文走术语库和翻译记忆；文件翻译的识字新增“Windows 自带识字”。
- 【扩展数据】扩展的笔记、高亮和本地导入的字幕改动后同步到清影（进备份）；新装扩展或刚连上清影时，本地没有的会自动取回。单份上限默认 10 MB，可以在“媒体库 → 备份与还原”里调（1–200 MB）；超过上限的那次不同步（扩展里的数据不受影响），原因和大小显示在那里。
- 【扩展：视频摘要面板】原来 2000 多行的 `vsum.js` 按标签页拆开：样式（`vsum-style.js`）、文稿、笔记、评论、生词、导图、“更多”各一个文件，主文件只留框架、通信和摘要 / 章节 / 问答。各页用到的面板状态和工具从参数传入，不再共享一大片闭包。

### 已知局限

- 桌面端截图窗和写作窗口还是自己轮询任务结果（没有改成推送）。
- “本机识字 + 翻译”和 Windows 自带识字只在 Linux 上跑了单元测试，没有在真实 Windows 桌面上验证。

## 1.7.0（扩展 1.18.0）

### 文件翻译

- 【版面画布】PDF 的“版面”改成画布：可以切换看“原文 / 译文 / 对比（左右同步）/ 导出效果”；Ctrl（⌘）+ 滚轮以鼠标为中心缩放，滚轮上下平移，按住拖动平移，还有“适应宽度 / 实际大小”；点一块译文就地修改（点别处保存，直接写进缓存，生成文件时用），双击一块重译。译文块放回原文的位置，盖上原文所在处取样的背景色，字用原文的颜色，放不下自动缩小字号。
- 【原文盖不干净】文字版 PDF 导出时，译文也先盖一层原文处取样的背景色再写（以前只删文字对象，图片里的字、描边字会透出来）。局限：背景是渐变或照片时，盖的是一块纯色，和周围会有色差；“导出效果”里能看到真实结果。

### 扩展

- 【文稿原文】选字幕轨时，视频有自动字幕（语音识别）轨，就按它的语言当作视频说的语言；以前标题是中文的英语视频会被当成中文视频，选中中文轨，文稿显示成中文。文稿里新增“原文 / 译文 / 双语”选择，原文始终保留；没翻译时选“译文”或“双语”会直接去翻译。鼠标放在文稿的原文上，下面对应的译文高亮。
- 【字幕学习】开启“学习（悬停字幕单词查词）”后，原文不再变小（词的样式被全局字号规则压成了 13px）。
- 【查词浮窗】加宽到 400px，按钮不再分行（录原声并进同一行）；例句除了“本句”，再加两种：本视频里含这个词的其他句子（点时间跳过去）和模型给的 2 个带译文的例句。
- 【生词】摘要面板切到“生词”页时主动刷新，不用再点“刷新”，已删除这个按钮。
- 【切换视频】YouTube、B 站这类站内跳转（页面不刷新）切到别的视频后，视频摘要自动重新读取新视频的字幕，旧视频的结果先存起来、字幕层关掉。

## 1.6.0（扩展 1.17.0）

### 模型池

- 【Google / 微软 / DeepL / DeepLX】这几家是机器翻译接口，不是对话接口，之前用“兼容 OpenAI”那一栏填会识别不了。现在模型池“添加服务”里有专门的四项：Google 翻译（Cloud Translation）、微软翻译（Azure Translator，另有“区域”一栏）、DeepL（免费版密钥以 `:fx` 结尾，自动走 api-free）、DeepLX（自建，填完整接口地址）。它们只用于翻译（字幕、网页、文件、屏幕），不会被摘要、问答挑中；按优先级和每日上限与对话模型一起轮换，额度用完（如 DeepL 456、Google 429）自动冷却并换下一家。测试按钮会真的译一句。限制：机器翻译用不上术语库和 AI 专家，需要术语一致时把对话模型排在前面。只测了请求格式和轮换（本机模拟服务），没有用真实密钥调过这四家的线上接口。

### 屏幕翻译

- 【文字被裁切、偏下】译文框以前就是原文那一小块，译文比原文长就被框裁掉；多行排版在框里还靠上贴边。现在译文框四周多留一圈，放不下就自己往下长（不再裁），单行文字上下居中，字号按放得下的最大值取。算法有单元测试；没在真实 Windows 桌面上对比过。

### 文件翻译

- 【版面预览】PDF 在阅读器里多了“版面”视图：把缓存里的译文（含你改过的）真的画到原来的页面上，左边原页、右边译文页，位置、字号、有没有盖住原文一眼就能看出来。文字版和扫描版都支持，用本机 PDFium 渲染，不生成文件；改了译文后点“刷新”。需要先安装 PDF 排版组件。其他格式（DOCX、EPUB、TXT、字幕）没有页面概念，仍是文字对照。
- 【任务里的“取消”】改成红色高亮按钮，进行中的任务一眼就能找到。

- 【保存译图】贴字层是“不进截图”的窗口（否则会被自己再识别一遍），所以系统截图、别的截图软件截不到译文。现在可以用“保存译图”（屏幕边上的小悬浮钮、设置页按钮、快捷键 Ctrl+Alt+S）：取一帧干净的画面，把译文按现在的排版叠上去，存到“下载文件夹/屏幕翻译截图”，同时复制到剪贴板。

- 【先预览，再生成】翻译完先停在阅读器里（可在设置里关掉这个开关）。点一下译文就能直接改，每段可以“重译”或“去掉”；满意后点“生成文件”，直接用改好的译文，已译的段落走缓存，很快。
- 【扫描版 PDF】识别出的文字和位置存成旁路文件，改完译文再生成不用重新识字、重新翻译。

- **批量下载快到结尾时变慢**：整批限速以前按“并发数”平分，收尾阶段只剩一两个任务时，每个任务仍只拿到“总限速 ÷ 并发数”的一小份，其余带宽闲着。现在 yt-dlp 下载按“这一批还没完成的任务数”分份额，剩得越少每个任务越快。若你没有设置整批限速，慢的原因不在这里（可能是站点单独限速、同站间隔或合并校验阶段），请把慢的那几条的站点和任务详情反馈给我。

- **AI 术语库（设置 → AI）**：让专有名词、行话在翻译里始终是同一个译法。①自建术语库：名称、适用的目标语言、只在哪些网站生效（写法与沉浸式翻译一致：`example.com`、`*.example.com`、完整网址带 `*`、`*`），逐条编辑原文 / 译文 / 说明（译文留空 = 保持原文不翻译），导入 / 导出 CSV（表头 `source,target,tgt_lng`，与沉浸式翻译互通，另有可选 `note` 列）。②社区术语库：直接从沉浸式翻译的公开术语库（GitHub `immersive-translate/terms`）安装，按“翻译成”的语言选对应版本，生效网站随库带入，可一键更新。③智能提取：贴一段文字、选一个字幕 / 文本文件或给一个网页地址，让模型挑出专有名词并给出建议译法，结果先进“待确认”，可逐条改译法后加入某个术语库或新建术语库，也可忽略；已在术语库里的不重复提醒。④提取网站：在设定的网站上翻译视频字幕 / 网页（网页需开启“翻译前先判断网页领域”）时，自动在后台提取术语，放进“待确认”或直接加入指定术语库，并记录最近提取时间和累计条数。⑤使用方式：翻译时只把**这一批文字里出现过**的术语（英文按整词、最多 40 条、长的优先）写进提示词，不会明显增加用量；自建术语优先于提取、提取优先于社区；设置里有总开关。应用端字幕翻译、扩展的网页翻译 / 视频文稿翻译、剪辑页的文稿翻译都会使用。
- **AI 专家（设置 → AI）**：给翻译换一套“策略”（提示词），默认【通用】。内置技术文档、学术论文、新闻资讯、金融财经、法律合同、医学健康、影视字幕、游戏、社交媒体、文学小说、电商商品、课程讲座、通俗易懂 13 位；可以自己新建 / 复制内置的再改，导入导出 JSON，也能直接导入沉浸式翻译的专家 YAML，或从其公开仓库（`immersive-translate/prompts`）按需安装社区专家（不随程序分发，该仓库未声明许可证）。选了“按网站自动选用”，默认是【通用】时会按网址换成匹配的专家（例如 github.com → 技术文档）。专家只补充用词、语气和格式处理，译文的输出格式由程序固定，不会因专家说明而乱。应用端字幕翻译、扩展的网页翻译都会使用。

- **字幕工坊 S2：编辑、内嵌、播放**：①字幕编辑器（媒体库详情 → 字幕标签页，工具箱 → 字幕工具 → 编辑）：表格里改文字和起止时间、拆分、合并、查找替换、撤销重做，保存前检查重叠 / 过长 / 时间倒置，保存时先留 `.bak`。②软字幕可一次内嵌多条轨道（mp4 → mov_text、mkv → srt / ass、webm → webvtt）；硬字幕（烧录）有样式预设，烧录前可先预览一帧，双语用 ASS，字号随画面高度缩放（需要带 libass 的 ffmpeg）。③内置播放器可切换双语 / 原文 / 译文 / 上下顺序，调字号和延迟。④解析页发现视频没有字幕时给出“生成字幕”入口，下载队列的媒体任务上也有按钮；识别模型（whisper）可在设置里下载和管理。命令行 / 接口新增 `--lang --translate --display --format --correct --mode --no-resegment`。
- **字幕工坊 S3：云端识别轮换、语义断句、反思翻译、逐词时间、扩展字幕层**：①设置 → AI → 模型池：服务新增“语音转文字模型”，“适用任务”勾选“语音转字幕（云端）”后参与云端识别的轮换（预设 Groq `whisper-large-v3-turbo`、硅基流动 `FunAudioLLM/SenseVoiceSmall`），额度 / 限流 / 网络失败自动冷却并换下一家。②生成字幕新增三个默认关闭的选项：语义断句（AI 只能插换行，一个字都不许改，改了就退回规则断句）、反思翻译（译完让 AI 对照原文检查润色，数字或长度对不上就保留初译，请求量约翻倍）、逐词时间（仅本机 whisper.cpp，把拆开字幕的分界对到真实词间停顿；命令行 `--semantic --reflect --word-timing`）。③浏览器扩展新增“视频字幕层”（弹窗按钮 / 右键菜单，按需注入）：在任意网页的视频上叠字幕，读取站内字幕，没有就让清影转写，用清影的模型翻译成双语，可调字号、位置、±0.5 秒延迟，并导出所见即所得的 SRT。④扩展翻译缓存的键现在包含“提示词版本”（模型、AI 专家、已启用术语库的指纹），换专家或改术语库后不会再命中旧译文。局限：云端接口没有逐词时间；没有卡拉 OK 式逐词高亮；语义断句、反思翻译、云端轮换都只用模拟接口测过，没有用真实服务联调。
- **翻译：各网站单独设置、更多语言**：①扩展 → 网页翻译设置新增“各网站单独设置”，每行 `域名 语言代码 [bilingual|replace]`（如 `github.com ja replace`，语言写 `-` 沿用全局），子域名跟随父域名、最长匹配的域名优先，没写的字段沿用全局设置。②应用里翻译目标语言（工具箱生成字幕、AI 设置）从 9 种扩到 20 种，并且可以直接输入任意语言名；字幕文件名里的语言标记新增葡萄牙语、意大利语、阿拉伯语、泰语、越南语、印尼语、土耳其语、波兰语、荷兰语、乌克兰语、印地语（其余仍标 `ai`）。扩展里的视频摘要 / 文稿翻译本来就支持 36 种语言任意互译，这次没有改动。
- **微信公众号文章视频（可选组件，默认关闭）**：设置 → 可选组件 里开启后，粘贴 `mp.weixin.qq.com` 文章链接即可解析其中的微信原生视频：读出页面里各清晰度的签名直链（超清 / 高清 / 流畅，同清晰度只留标准编码），下载自动带微信 Referer，一篇多个视频会分开列出；遇到“环境异常”拦截、腾讯视频嵌入、视频号卡片会给出明确提示。关闭时这个平台完全不参与识别。视频号暂不支持：文章里的视频号卡片只带封面与标识，匿名的预览接口（get_feed_info）也只返回封面和描述、不含视频地址，后续再研究。已用一篇真实文章确认：视频号卡片会得到明确提示；原生视频直链的解析仍只用按公开项目思路构造的页面样本测试过。

## 0.8.0

这一版的主题是**下载引擎打磨**：哈希校验、备用地址、自动降级、边下边播。详细说明见 [docs/download-engine.md](../docs/download-engine.md)，规划见 [docs/roadmap.md](../docs/roadmap.md)。

**新增**
- **哈希校验**：链接里写 `#sha256=…`（或 md5 / sha1 / sha512、`?md5=…`、`#checksum=算法:值`），下载完成后流式校验，不一致自动重下一次，仍不一致报错；本机接口 `/api/grab` 支持 `checksum` 字段
- **备用地址**：`#mirror=<地址>`（可重复）或 `/api/grab` 的 `mirrors`，主地址失败后按顺序换用
- **按域名记住并自动降级**：服务器不支持 Range 记 7 天；连接数受限（429 / 503 / 重置）时自动减少连接继续下载，并记住该域名的可用连接数 30 天

- **边下边播**：下载中或已暂停的单个 HTTP 音视频文件，在队列里点“边下边播”即可在内置播放器里看已下载的部分，拖到没下到的位置会等待下载追上
- **链接直接是文件时不再走站点解析**：`.zip`、`.iso`、`.exe` 等直链按普通文件处理

**代理**：核实并补全了测试：HTTP 代理、SOCKS5（含用户名密码、`socks5h://` 代理端解析域名）、按网站分流都有测试覆盖；设置页补充了说明。**交给 ffmpeg 的流（http(s) 直播流、rtmp、rtsp）现在也按分流规则走代理**：清影在本机起临时转发桥，经 HTTP / SOCKS5 代理转出，ffmpeg 抓取和直播预览不再因为不走代理而看不到；设为直连时会清掉 ffmpeg 继承的代理环境变量。

**文档**：扩展商店上架文案和隐私政策（`docs/release-guide/store-listing.md`、`privacy-policy.md`）补上了接管浏览器下载（`downloads` 权限）、视频发现（`webRequest`、`tabs`）和内容脚本的说明与权限理由。

**说明**：FTP / SFTP / BT / ed2k 暂不走代理；rtmps / rtsps 不能经代理（会明确报错）；“系统代理”出口下的 ffmpeg 流只认环境变量 `http_proxy`；`socks5://` 在本机解析域名，需要代理端解析请用 `socks5h://`；MP4 索引在文件末尾时不能边下边播；音视频分开下载的任务不做哈希校验；浏览器扩展暂不发送哈希和备用地址。

## 0.7.0

这一版的主题是**协议扩展**：除了网页视频和 HTTP 文件，现在 FTP / SFTP、BT / 磁力、ed2k、thunder:// 等链接粘贴进来就能下载。详细说明见 [docs/protocols.md](../docs/protocols.md)，规划见 [docs/roadmap.md](../docs/roadmap.md)。

**新增**
- **FTP / SFTP**：`ftp://`、`sftp://` 链接（可带 `user:pass@`），支持断点续传、限速和取消；SFTP 首次连接记住服务器指纹，之后指纹变化会拒绝连接
- **专用链接解码**：`thunder://`（迅雷）、`flashget://`（快车）、`qqdl://`（旋风）自动解码成原链接再下载
- **RTMP / RTSP / MMS 等流**：交给 ffmpeg 抓取，与直播录制共用

- **Tracker 列表自动更新**（“设置 → BT 与 ed2k”）：默认从 ngosang/trackerslist 的 best 列表更新（经 jsDelivr / GitHub），默认 7 天一次，可改间隔、可手动“立即更新”、可增删列表来源和自己的 tracker；更新失败保留上次的列表；只接受 udp / http / https 地址并去重

**说明**：BT 和 ed2k 的下载速度取决于网络里有没有可用的来源；ed2k 公开服务器已经很少，需要自己配置可用的服务器。ed2k 不支持低 ID 来源、Kad 网络和搜索；BT 暂不支持代理，不支持直接拖入本地 .torrent 文件。

## 0.4.0

这一版新增了整栏的**剪辑**（时间线剪辑、叠加多条素材、实时预览、动态区域感知），以及视频规整、LUT 工作室、调试包的多项更新，所以版本号从 0.3.x 提到 0.4.0。

**新增**
- 视频规整：分段色彩匹配。混剪、多来源拼接的视频里，各个镜头偏色、亮度、对比度、饱和度不一致时，找出和整体不一致的镜头，只把它们单独校正到和整体一致，一致的镜头原样不动（[说明](../docs/video-normalize.md)）。详细设置里可调强度，“检测第一个文件的色彩差异”能先看时间轴和每个镜头的问题，可以取消不想校正的镜头，并能看校正前后的对比；新增“混剪 / 多来源拼接”预设
- LUT 工作室（工具箱新标签，[说明](../docs/lut-studio.md)）：用一张示例图片（或视频里的一帧）边看边调，生成新的 `.cube` 3D LUT。基础调色有曝光、黑场 / 白场、中间调、对比度、阴影 / 高光、色温 / 色调、饱和度、自然饱和度、色相、分色调、整体强度，附七个一键风格；可以先叠加别人的 `.cube` 作为基底再调整；也可以选一张参考图，让示例图片的明暗分布和整体色彩向它靠拢。预览和 ffmpeg 的 `lut3d` 用同样的四面体插值，看到的就是文件的真实效果；可保存 17 / 33 / 65 格点的 `.cube`，把同样的效果导出成 png / jpg / webp 图片，或一键带到视频规整里使用
- 调试版现在使用独立的程序标识（`com.dixuanaoyi.clearclip.debug`，产品名 ClearClip Debug），和已安装的清影互不干扰，不会再被已经开着的正式版挡住；窗口标题和侧栏左下角显示版本号和提交号，一眼能确认运行的是哪一次构建
- 调试版流水线 `desktop-debug`：往 `claude/**`、`debug/**` 分支推送且提交说明带 `[debug-build]`，或在 Actions 里手动运行，就会构建 Windows 便携调试包（带控制台窗口和开发者工具），上传成 Actions 产物，不用合并、不用发版（[说明](../docs/debug-build.md)）

- 视频规整：新增**输出电平**——16–235（电视范围，默认，游戏、影视美术、投稿平台等的常见要求）/ 0–255（全范围）/ 沿用素材。全范围的素材选 16–235 会压回电视范围；电视范围的素材选 0–255 会拉开，输出文件里写明对应的范围标记。色阶、LUT、HDR 转 SDR 都先在电视范围里做完，最后一步才拉开。以前“补全色彩信息”里附带的“全范围转电视范围”现在由这个选项控制（默认行为不变）
- 视频规整：新增**降噪**（关闭 / 弱 / 中 / 强 / 高质量）。弱 / 中 / 强用 `fftdnoiz`（精简版和完整版 ffmpeg 都有），高质量用 `nlmeans`（画质最好、速度约为四分之一）；缺滤镜时依次退到 `hqdn3d`、`atadenoise` 并提示。降噪放在缩放之前（缩小时放在之后）和色阶、LUT 之前；预览会先预热半秒再截图，和实际处理一致。[说明里有“噪点多怎么办”的建议](../docs/video-normalize.md)
- 视频规整：分段色彩匹配可以**按镜头单独调节**：检测出的不一致镜头各有一个“单独调节”开关，打开后这个镜头用自己的自动校正强度和亮度 / 对比度 / 饱和度 / 色温 / 色调；没有单独调节的镜头都用**统一调节**（同样五项）。取代了原来的“取消勾选就不校正”（把单独调节里的自动校正强度拉到 0 即可达到同样的效果）
- 视频规整：分段色彩匹配可以在检测之前**预先设置排除的时间段**：按时间（`0:03 – 0:06`，结束留空 = 到结尾）或按帧号（第几帧到第几帧，从 1 开始、含首尾）填写。排除的时间不计入“整体”的基准、不被标成不一致，自动校正、单独调节和统一调节都绕开它，保持原样；一个镜头只有一部分被排除时，其余部分照常校正。时间轴上用斜线标出排除的段，不一致的镜头可以一键“排除这个镜头”，改了排除的时间会自动重新检测（不重新解码整个文件）。默认只对第一个文件生效，可以勾选对所有文件生效。这里的“帧区域”按“第几帧到第几帧”理解，不是画面里的某块区域
- **剪辑**（工具箱新标签，[说明](../docs/video-edit.md)）：时间线剪辑。把多段视频 / 图片按顺序排在时间线上，拖动片段边缘或填入点 / 出点来裁剪，`S` 分割，拖动调整顺序；每个片段可调速度（0.25×–4×）、音量、静音、淡入淡出、画面方向（旋转 / 翻转）、亮度 / 对比度 / 饱和度；片段之间可加 16 种转场（淡入淡出、闪黑、闪白、溶解、擦除、滑动、圆形、时钟、马赛克）；加文字（时间、位置、字号、颜色、描边、底色块、字体，可直接在监视器里拖动）和配乐（开始时间、裁剪、音量、淡入淡出、循环、片段里有人声时自动压低）；输出尺寸（含竖屏、方形）、帧率、画面适配（留黑边 / 铺满裁切 / 模糊背景）、画质、H.264 / H.265、MP4 / MKV 可选。监视器是**实时画面**：转场、叠加、文字、调色、配乐直接合成在里面，改完参数马上能看到，不用先“生成预览”；要逐帧核对再点“生成精确预览”，用和导出同一套流程渲染一份低分辨率的成片；撤回 / 重做、保存成 `.ccedit` 工程文件、素材找不到时标红并可重新指定、草稿自动保存。媒体库里的视频详情新增“放进剪辑…”
- **动态区域感知**（剪辑里选中视频片段后的“区域”标签，[说明](../docs/video-edit.md)）：在一个镜头里框出一个物体（点程序感知到的运动物体，或自己拖一个框），程序在整个片段里持续追踪它的位置，再把效果绑在这条轨迹上：马赛克 / 模糊（遮走动的人脸、车牌）、局部调色（可以改成“作用于区域以外”）、跟随聚焦（放大并跟着物体走，也可以按成片的比例把横屏素材裁成竖屏）。形状（方形 / 椭圆）、边缘羽化、范围扩大、生效时间可调；追偏了就把红线移到那一刻、在监视器里把框拖回物体上，留下一个不会被重新追踪改掉的“手动点”，再从这一帧重新追踪；追踪不到的位置会标出来，并能一键跳过去。位置按占画面的比例、时间按素材自己的时间保存，分割、裁剪、变速、旋转、翻转之后仍然对得上；一个片段最多 8 个区域。导出前先在本机按轨迹逐帧生成遮罩，再由 ffmpeg 合成，所以形状、羽化、“作用于区域以外”都准确
- **剪辑：叠加素材（画中画、贴纸、水印、GIF）**：主轨上面可以叠加多条视频 / 图片 / GIF，放在任意时间、任意一条叠加轨（最多 8 条、100 个素材）上，不再只能排在末尾的一行。素材不够用一条轨道时同时出现多条；位置、大小、旋转、翻转、不透明度、淡入淡出、速度、音量、亮度对比度饱和度都能单独调，选中后可以直接在监视器里拖动、缩放、旋转；GIF 默认循环并静音。可以把主轨上的片段“移到叠加轨”，叠加素材也能“移到主轨”。文字画在所有叠加素材之上，叠加素材不会把成片拉长（[说明](../docs/video-edit.md)）
- **剪辑：把文件直接拖到时间线**：从资源管理器 / 访达拖文件，落在哪一行就放进哪一行（叠加轨从落点的时间开始，主轨按落点插入，音频行当配乐），拖动时高亮落点；一次选多个文件时，它们在同一条轨上依次排开，轨道被占了自动换到最近的空轨
- **剪辑：实时预览**：监视器直接合成主轨、叠加素材、转场、文字、调色、淡入淡出、音量、区域效果和跟随聚焦，不用每次点“生成预览”再等渲染。它是近似效果，“精确预览”（原来的“预览成片”）保留为可选项，需要逐帧核对时再生成
- **剪辑：支持更多素材格式**：视频增加 3G2、MTS / M2TS、OGV、VOB、F4V、ASF、DIVX、MXF，图片增加 JFIF、TIFF、AVIF、HEIF，音频增加 AIFF、AC3、MKA、AMR，加上原有格式（含 GIF、WebP、BMP、HEIC）；文件对话框、拖放、媒体库的素材都按同一份清单识别。能不能读最终由 ffmpeg 决定，读不出来的（比如没有解码器的 AVIF / HEIC）会明确提示，建议先转成 PNG / JPG
- 滤镜图很长（分段色彩匹配的镜头很多）时写进临时文件交给 ffmpeg（新版 `-/filter_complex`，旧版 `-filter_complex_script`），避免超出 Windows 命令行约 32K 字符的上限

**修复**
- 视频规整：全范围的 `yuvj420p` 素材选 0–255 输出时，格式转换会把它悄悄压成电视范围；现在转换前明确写成“范围不变”
- 视频规整：“放进目标框并用模糊背景补边”（竖转横 / 横转竖的模糊背景）在精简版（LGPL）ffmpeg 里会失败——这类 ffmpeg 没有 `boxblur`（它是 GPL 滤镜）；现在没有 `boxblur` 时改用 `gblur`，模糊程度接近。这个问题在 0.3.0 / 0.3.1 里就有，是做剪辑的“模糊背景”时用精简版实测发现的

**注意**
- 分段色彩匹配用统计的办法判断“整体”，画面内容本来就不同色调的镜头可能被误判，所以只处理偏离超出正常范围的，强度可调，可以逐个单独调节；HDR 素材暂不支持
- 降噪的参数是用加了随机噪点的合成画面标定的，没有在真实的夜景 / 高 ISO 素材上逐档调过，实际效果请先用“预览对比”看；新的输出电平、降噪和单独调节只在 Linux 上用真实 ffmpeg 测过（系统自带的 6.1 和 BtbN 的 N-127252 两个版本），没有在 Windows / macOS 上跑过
- 剪辑的实时画面是近似预览：转场的形状是对着 ffmpeg 的输出量出来的近似（溶解、马赛克用淡入淡出代替），调色、字体、淡入淡出也是近似，配乐的压低听不出来，高于 100% 的音量按 100% 播放，“模糊背景”显示成留黑边，以“精确预览”和导出的成片为准；实时画面能不能播某个素材取决于系统 WebView 的解码能力，播不出来的会提示并用静态画面代替，导出不受影响。叠加素材的位置、大小等是固定值，没有关键帧，也没有波形；叠加素材不能加转场和区域；HDR 素材不做 SDR 转换（先用视频规整）。剪辑只在 Linux 上用真实 ffmpeg 6.1 做过导出测试，界面用 Chromium 加模拟后端测过，**没有在 Windows / macOS 的真实窗口里操作过**；导出用系统自带的 6.1（完整版）和 BtbN 的 N-127252（精简版，没有 libx264，用 libopenh264 编码）各跑了一遍全部真实 ffmpeg 测试（包括叠加素材的导出）；实时画面只在 Chromium 里测过，Windows（WebView2）和 macOS（WKWebView）上的视频解码、CSS 滤镜和遮罩细节可能与此略有不同
- 动态区域感知用的是传统图像算法（帧差找运动物体、模板匹配做追踪），不是 AI 识别：不认识人脸 / 人 / 车，看不见静止不动的物体，镜头大幅移动或变焦时感知不出单独的物体；追踪在物体被长时间挡住、形状变化很大、框里几乎是纯色、运动模糊严重时会丢，框的大小追踪时是固定的，物体明显变大变小要靠手动点和调整大小校正。实时画面里区域效果只是示意（不显示羽化和“作用于区域以外”，跟随聚焦没有算镜头平滑），以“精确预览”和导出为准。视频规整的分段色彩匹配还不能排除画面里的某块区域。算法用合成画面（带纹理的移动物体，加平移、遮挡、噪点）和真实 ffmpeg 渲染的合成视频测过，**没有在真实拍摄的素材上逐类调过参数**；导出在 Linux 上用系统 ffmpeg 6.1 和 BtbN 的精简版各跑了全部测试，界面用 Chromium 加模拟后端（追踪结果是模拟的）测过，没有在 Windows / macOS 的真实窗口里操作过
- 手动调节（亮度、对比度、饱和度、色温、色调）是 YUV 里的近似，不等同于专业调色软件的色彩科学

## 0.3.0

**新增：视频规整**（[说明](../docs/video-normalize.md)）
- 工具箱新增“视频规整”：把手机录屏、直播录制、平台下载的成片统一成同一规格。选好文件后按检测结果（可变帧率、HDR、色彩标记、黑边、响度……）自动推荐预设，预设有通用兼容、剪辑素材统一、手机录屏、直播录制、平台下载成片、竖屏短视频、横屏 1080p、省空间（HEVC）；可批量，已符合规格的文件不重新编码
- 可单独调：画面尺寸（缩小 / 补黑边 / 模糊背景补边 / 铺满裁切）、帧率（可变帧率转标准固定帧率）、HDR 转 SDR、色彩标记补全与修正、自动色阶、`.cube` LUT（可调强度）、自动去黑边、采样率 / 声道 / 响度、音画不同步与时间戳修正、编码与质量；预览区抽一帧对比处理前后
- 防抖：vidstab 两遍防抖，没有 vidstab 时退回 deshake
- 可接进自动规则（下载完成后自动规整）和直播录制（录完自动规整）；媒体库多选或单个条目详情里都能直接送去规整
- 设置 → 组件：显示 ffmpeg 的版本、精简 / 完整版本、HDR 转换 / LUT / 防抖 / 硬件编码的可用情况；可以切换到完整版（GPL，带 x264、x265、vidstab、zscale，由用户主动下载，不随清影分发）；macOS 请用 Homebrew 安装
- 精简版 ffmpeg 下的兜底：没有 x264 时优先用试编码通过的硬件编码器（NVENC / QuickSync / AMF / VideoToolbox），再退到 openh264；没有 zscale 时用程序内置的 3D LUT 做 HDR → SDR；没有 vidstab 时用 deshake

**注意**
- 硬件编码器没有在真实设备上测过；完整版 ffmpeg 的下载流程只在本地用现成的 ffmpeg 验证了检测和使用，没有走过完整的下载安装
- 内置 LUT 的 HDR → SDR 与 zscale 的结果接近但不完全一样

## 0.2.0

在 0.1.1 的基础上补充了媒体库、媒体工具、AI、自动化、网络、安全与隐私、桌面体验几组功能。每组的详细说明见 `docs/` 下的对应文档。

**媒体库与整理**（[说明](../docs/library-and-tools.md)）
- 标签、收藏、评分、备注；导入已有文件夹；磁盘统计；回收站；按规则整理文件夹
- 重复文件检测（内容哈希 + 画面相似）；字幕全文搜索；预览图与镜头拆分；导出 CSV / JSON；备份与还原

**后处理与媒体工具**（[说明](../docs/library-and-tools.md)）
- 工具箱：压缩、GIF、竖转横、倍速、响度、旋转、转封装、截图、拼接、裁剪、去音轨、音频标签
- 字幕工具（平移、校准、双语合并、格式互转、弹幕 XML 转 ASS）；弹幕样式
- 设置大小上限后自动选不超过上限的最高清晰度；下载失败时自动降一档重下

**AI**（[说明](../docs/library-and-tools.md)）
- 语音转文字（在线接口或本机 whisper.cpp）、字幕翻译、摘要与章节、把章节写进视频；接口密钥加密保存

**自动化与集成**（[说明](../docs/automation.md)）
- 推送通知（Telegram、Bark、Server酱、企业微信、钉钉、飞书、ntfy、Webhook）
- 下载完成后自动上传（WebDAV 或复制到另一个文件夹）、自动规则、自定义站点规则
- 播客 / RSS 订阅、直播预约录制、订阅保留策略
- HTTP 接口 v1、局域网网页控制台、命令行（`clearclip add / list / status / pause / resume / cancel / remove / search`）
- 浏览器扩展 1.2：嗅探页面里的视频流和视频文件，一键发送

**网络与稳定性**
- 限速计划（按星期和时段）、省流量模式、线路测速

**安全与隐私**（[说明](../docs/security-and-privacy.md)）
- 应用锁（启动即锁、空闲自动锁、老板键）、隐私模式、加密保险箱（Argon2id + 分块 AES-256-GCM）、一键清除

**桌面体验**（[说明](../docs/desktop-experience.md)）
- 首次引导、命令面板（Ctrl+K）、任务详情、内置播放器（支持字幕）、悬浮拖拽窗、托盘显示总速度
- 英文界面（设置 → 通用 → 语言）

**安装包**
- macOS 改为一个同时支持 Apple 芯片和 Intel 的通用安装包（`_universal.dmg`）
- 新增 Windows ARM64 安装包和便携版（实验性）

**已知限制**
- 英文界面是机器翻译，后端返回的错误消息等动态文字仍是中文
- 内置播放器能否播放 H.264 取决于系统自带的解码器
- 安装包没有代码签名（macOS 为临时签名），首次运行说明见 Release 页面
