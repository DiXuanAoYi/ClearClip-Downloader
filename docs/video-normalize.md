# 视频规整

音频有“响度标准化”，视频也有对应的一套：**把来源不同的素材统一成同一个规格**，导入剪辑软件、上传平台、放进手机都不出毛病。入口在“工具箱 → 视频规整”，也可以从媒体库多选后批量规整，或者用自动规则、直播录制结束后自动规整。

规整会生成**新文件**（默认 `原名.规整.mp4`，放在原文件旁边），不会改原文件。已经符合规格的文件不会重新编码，没有需要改的会直接告诉你。

## 三类素材各自常见的问题

| 来源 | 常见问题 | 规整怎么处理 |
| --- | --- | --- |
| 手机录屏 | 可变帧率（导入剪辑软件后音画越来越不同步）、横竖屏切换留下的黑边、旋转标记、单声道 / 44.1 kHz | 可变帧率 → 最接近的标准固定帧率；自动去黑边；音频统一为 48 kHz 立体声 |
| 直播录制（FLV / TS） | 时间戳跳变、音画不同步、容器不通用、各场音量不一致 | 修正时间戳并重新对齐音画；转成 MP4；响度统一到 -16 LUFS；视频本身没问题时不重新编码，只换容器 |
| 平台下载的成片 | HDR（在普通显示器上发灰）、色彩标记缺失或错误、成片自带的黑边、编码不通用 | HDR → SDR；补全 / 修正色彩标记；去黑边；其余保持原样 |

## 一键规整：预设

选好文件，界面会根据检测结果**自动推荐一个预设**（检测结果也会列出来：分辨率、帧率是否可变、是否 HDR、色彩标记、黑边、响度……），也可以自己换。预设只是一组默认值，下面的各项还能再调。

| 预设 | 做什么 |
| --- | --- |
| 通用兼容 | H.264 / 8 位 / BT.709，HDR 转 SDR，可变帧率转固定帧率，超过 1080p 的缩小到 1080p |
| 剪辑素材统一 | 1920×1080（竖屏 1080×1920）、固定 30 帧、48 kHz 立体声、-16 LUFS，去黑边 |
| 手机录屏 | 可变帧率转固定、去黑边、音频 48 kHz 立体声 |
| 直播录制 | 修正时间戳和音画同步、转 MP4、-16 LUFS；视频不重新编码 |
| 平台下载成片 | HDR 转 SDR、去黑边、补全色彩信息；没有需要改的就不重新编码 |
| 竖屏短视频 1080×1920 | 比例不符的用模糊背景补边，30 帧，48 kHz 立体声，-14 LUFS |
| 横屏 1080p | 1920×1080，模糊背景补边，固定帧率，48 kHz 立体声，-14 LUFS |
| 混剪 / 多来源拼接 | 把偏色、偏亮、饱和度和整体不一致的镜头单独校正到和整体一致（见下面“分段色彩匹配”），同时去黑边、补全色彩信息；视频本身不缩放、不改帧率 |
| 省空间（HEVC） | 重新编码成 HEVC，同样画质体积通常小三成以上；需要 ffmpeg 有 HEVC 编码器 |

**批量**：可以一次选很多个文件。整批用同一套设置（默认取这批文件里被推荐最多的那个预设），但每个文件只做它自己需要的：不是 HDR 的不转色调，本来就是固定帧率的不动帧率，已经符合的不重新编码，没有需要改的会直接告诉你。素材类型差得很远（比如录屏和 HDR 成片）时，分开规整更合适。

## 可单独调的项目

- **画面尺寸**：不改 / 只缩小（按短边设上限）/ 放进目标框补黑边 / 放进目标框用模糊背景补边 / 铺满目标框并裁掉多余部分。竖屏素材的目标框自动按竖屏翻转。
- **帧率**：不改 / 自动（可变帧率转成最接近的标准帧率：24、25、30、50、60……本来就是固定的不动）/ 统一成指定帧率。
- **HDR → SDR**：检测到 PQ（HDR10 / 杜比视界的兼容层）或 HLG 时，转成 BT.709 的 SDR。做法见下面的“限制和解决办法”。
- **补全 / 修正色彩标记**：很多下载来的文件没有标明色彩空间，播放器猜错就会偏色或发灰。这里补上 BT.709 标记，高清素材的 BT.601 画面会转成 BT.709。只缺标记、画面本身没问题时，不重新编码，只改标记。
- **输出电平**：16–235（默认）/ 0–255 / 沿用素材，见下面的“输出电平”一节。
- **降噪**：关闭 / 弱 / 中 / 强 / 高质量，见下面的“降噪：噪点多怎么办”一节。
- **自动色阶**：把偏灰的画面拉开对比度，强度 0–100%。对已经色彩丰富、亮度范围本来就够的素材几乎没有效果，这是正常的。
- **分段色彩匹配**：镜头之间偏色、亮度、对比度、饱和度不一致时，把不一致的镜头单独校正到和整体一致，见下面的专门一节。
- **LUT 调色**：选一个 `.cube` 文件，可调强度（0–100%）；预览里能看到前后对比。没有现成的 LUT 可以用[LUT 工作室](lut-studio.md)自己调一个，保存后点“用于视频规整”会直接带过来。LUT 在 SDR 画面上应用，素材是 HDR 时先转 SDR 再套 LUT。
- **自动去黑边**：在素材里取多个位置检测，取所有位置的并集，只有黑边至少 8 像素并且占画面 2% 以上才裁，避免把暗场景误裁。
- **音频**：采样率、声道数、响度标准化（两遍 loudnorm，目标 LUFS 可调）。
- **修正音画不同步和时间戳跳变**。
- **视频编码与质量**：保持 / H.264 / HEVC；体积小 / 均衡 / 画质优先。

**预览**：在预览区抽一帧，左边是处理前（普通播放器里看到的样子），右边是处理后，下面写着会做哪些处理。预览只处理一帧，很快。

## 输出电平：16–235 还是 0–255

视频里的亮度有两种“刻度”：**电视范围（limited / tv）**把黑放在 16、白放在 235；**全范围（full / pc）**把黑放在 0、白放在 255。游戏、影视美术、投稿平台和大多数剪辑流程要求的是 16–235，所以这是**默认值**；0–255 只在明确要求全范围时才选。

- **16–235**：全范围的素材（手机录屏、一些屏幕录制软件、部分相机）会压回电视范围；本来就是电视范围的素材不动。输出文件里写明“电视范围”，播放器和剪辑软件不会再猜。
- **0–255**：电视范围的素材拉开到全范围（黑 16 → 0、白 235 → 255），输出文件里写明“全范围”。色阶、LUT、HDR 转换这些步骤都先在电视范围里做完，最后一步才拉开，避免来回取整。
- **沿用素材**：素材是哪种就输出哪种，不转换。

**要注意**：8 位画面里，16–235 拉开到 0–255 会让相邻的灰阶间隔变大，平滑的渐变（天空、阴影）可能出现轻微的色带，这是 8 位视频本身的限制，不是清影的问题；另外有些播放器、剪辑软件和网站对全范围视频的处理不一致，可能显示得发灰或过曝。没有明确要求就保持默认的 16–235。没有范围标记的素材按电视范围处理。

## 降噪：噪点多怎么办

先判断噪点从哪来，处理的办法不一样：

| 噪点的样子 | 常见原因 | 建议 |
| --- | --- | --- |
| 细碎的、彩色的颗粒，暗处特别明显 | 夜景、室内暗光、手机拍摄时 ISO 很高 | 用“中”；很重（几乎看不清暗部）用“强” |
| 轻微、均匀的颗粒 | 白天拍摄的轻度噪点，或轻度压缩 | 用“弱” |
| 一块一块的、物体边缘有“蚊子”一样的杂点 | 压缩过度的下载视频、反复转码过的视频 | 用“弱”或“中”；降噪能淡化但治不了根，最好重新找高码率的原片 |
| 老录像带、扫描片的雪花 | 模拟信号 | “强”或“高质量”，细节损失难免 |

**在清影里怎么做**：“详细设置 → 画面 → 降噪”选一档，再到下面的“预览对比”里看效果（预览会先读半秒预热，和实际处理的结果一致）。**从弱开始往上加**——档位越高，毛发、文字、布料纹理这些细节被抹掉得越多，画面会发“塑料感”。

四个档位的做法（参数是用加了随机噪点的合成画面标定的，不是真实素材的实拍测试）：

- **弱 / 中 / 强**：`fftdnoiz`（频域降噪：把画面切成小块做傅里叶变换，滤掉幅度低于阈值的成分），强度 4 / 8 / 14。精简版和完整版 ffmpeg 里都有，速度比较快（本机合成素材上 720p 约 37 帧/秒，4 核）。
- **高质量**：`nlmeans`（非局部均值：在画面里找相似的小块来平均），画质最好、细节保留最多，但**慢得多**（约为上面的四分之一速度），适合短素材。
- 如果 ffmpeg 没有 `fftdnoiz`，会退到 `hqdn3d`（完整版里有），再退到 `atadenoise`（时域平均，只适合镜头基本不动的画面），并在任务说明里提醒“改用了效果稍弱的替代做法”；一个降噪滤镜都没有时给出警告，不会让任务失败。

**处理顺序**：降噪放在缩放之前（不缩放或放大时，噪点要在被放大之前去掉；缩小时放在缩小之后，更快，缩小本身也会压低噪点），在自动色阶和 LUT 之前——这样提亮暗部时不会把噪点一起放大。降噪会让重新编码出来的文件更小，因为噪点很占码率。

**拍摄时**更有效的办法：降低 ISO、加光、避免过度的数码变焦；后期降噪只能补救，不能无损还原。

## 分段色彩匹配：镜头之间色彩不一致

混剪、多来源拼接的视频，各个镜头来自不同的设备、不同的调色，有的偏黄、有的偏蓝、有的特别亮或者发灰。这种问题不是整体处理能解决的，要**找出和整体不一致的镜头，单独校正它们**，一致的镜头原样不动。

在“详细设置 → 色彩 → 分段色彩匹配”里调强度（0 为关闭，默认的“混剪 / 多来源拼接”预设是 80%），这个滑块是**统一的自动校正强度**。如果有不想参与的时间（片头片尾的 Logo、黑场、故意调过色的段落），先在“排除的时间段”里填好（见下面一段）。点“检测第一个文件的色彩差异”可以先看结果：

- 一条时间轴，和整体不一致的镜头标成橙色
- 每个不一致的镜头列出问题：偏黄 / 偏蓝 / 偏红 / 偏绿 / 偏青 / 偏品红，偏亮 / 偏暗，对比度偏高 / 偏低，饱和度偏高 / 偏低
- “看对比”会在这个镜头中间截一帧，显示校正前后的样子

**排除的时间段（保持原样）**

“排除的时间段”可以在检测之前预先设置，一段一行，每行选“时间”或“帧号”：

- **时间**：`开始 – 结束`，写法是 `5`、`0:05`、`1:02:03.5`。开始留空 = 从头开始；结束留空 = 一直到结尾。
- **帧号**：`起始帧 – 结束帧`，帧号**从 1 开始、含首尾两帧**（`1 – 75` 就是开头的 75 帧）。按这个视频的帧率换算成时间，换算结果会显示在这一行后面。可变帧率的视频换算只是近似值，要求精确时直接填时间。这里的“帧区域”指的是**第几帧到第几帧**，不是画面里的某块区域。

排除的时间有三个效果：落在里面的镜头（一半以上被排除就算）**不计入“整体”的基准**，也**不会被标成不一致**；校正（自动校正、单独调节、统一调节）**都绕开这些时间**，哪怕一个镜头只有一部分被排除，被排除的那一段也保持原样、其余部分照常校正。时间轴上用斜线标出排除的段。

- 检测结果里每个不一致的镜头有“排除这个镜头”，一键把它的时间加进来；改了排除的时间，已经检测过的结果会自动重新检测（不用重新解码整个文件）。
- 排除的时间是按**第一个文件**的时间记的；同批有多个文件时勾选“对所有文件都排除这些时间”，才会对每个文件都生效（帧号按各自的帧率换算）。
- 最多 50 段，重叠的会合并；排除掉太多时间导致剩下的镜头不到 3 个时，会说明没法比较，不做自动校正（统一调节仍然会做，同样绕开排除的时间）。

**统一调节与单独调节**

- **统一调节**：亮度、对比度、饱和度、色温、色调五项手动调节（各 -100% 到 +100%，全 0 就是不额外调节）。**所有没有单独调节的镜头都用这一组参数**，包括检测不出差异的镜头；检测出来不一致、但没有勾选单独调节的镜头，先按统一的强度自动校正，再叠加统一调节。
- **按镜头单独调节**：检测出的每个不一致的镜头前面有“单独调节”勾选框。勾选以后，这个镜头不再用统一的手动调节，而是用自己的：一个自动校正强度（默认等于统一强度，拉到 0 就是这个镜头不做自动校正），加上自己的一组五项手动调节。
- 单独调节只能选**检测出来的**镜头；换了第一个文件，或重新检测后已经不在结果里的镜头，单独调节会清掉。单独调节的镜头是按第一个文件的检测结果记的，同批的其他文件只用统一调节。
- 手动调节是在 YUV 里做的近似（亮度平移、对比度缩放、色温和色调平移 U / V、饱和度缩放 U / V），不是专业调色软件里的色彩科学，要精细调色请用[LUT 工作室](lut-studio.md)。

**怎么判断“整体”和“不一致”**

1. 只解码关键帧，把每一帧缩成 64×36 的小图（几秒到几十秒）；关键帧太少的视频（录屏、直播录制常见）改成按时间间隔抽样，慢一些。
2. 相邻两个样本的色调变了，就当作换了一段；每一段取亮度、对比度、饱和度、偏色的中位数。偏色用画面里中等亮度像素的色度“中间一半的平均值”估算，少数鲜艳的物体影响不大。
3. “整体”是所有镜头按时长加权的中位数。某个镜头在某一项上偏离整体超过正常波动范围（亮度约 16 级、偏色约 7 级、饱和度约 1.6 倍）才算不一致。超过六成的镜头都不一致时说明没有明确的主体色调，不做处理。
4. 校正只动不一致的那几项：亮度整体平移、对比度缩放、偏色平移 U / V、饱和度缩放 U / V，强度决定向整体靠拢多少。用带时间窗口的 `lutyuv` 滤镜只作用在这个镜头上，镜头分界再用场景检测精确到帧。

**限制**

- 画面内容本来就不同色调的镜头（比如蓝天和绿草地）有可能被误判成偏色，所以只处理偏离超出正常范围的、强度可调、可以逐个取消。
- 没有硬切的渐变、淡入淡出过程中的色调变化检测不到；比关键帧间隔还短的镜头可能漏掉（大多数平台成片在镜头切换处都有关键帧）。
- 把不同色彩空间（比如一段 BT.601、一段 BT.709）拼在一起造成的色相偏差，只能靠偏色和饱和度的校正近似地拉回来，不是严格的色彩空间转换。
- HDR 素材要先转成 SDR，暂不支持对 HDR 画面做分段匹配。
- 校正只改画面，原来的帧率、声音不受影响；校正过的镜头需要重新编码整段视频。
- 每个要校正的镜头在滤镜图里是一段 `lutyuv`，不一致的镜头超过 150 个时说明没有明确的整体色调，不做自动校正；单独调节最多 100 个；滤镜图太长（超过约 12000 个字符）时会改为写进临时文件交给 ffmpeg，避免超出 Windows 命令行约 32K 字符的上限。

## 防抖

手持拍摄的抖动画面可以单独防抖（轻微 / 标准 / 强力）：先分析抖动，再平滑并适度放大裁掉边缘，音频不动。有 vidstab 时两遍处理，效果好，耗时约为视频长度的 1–2 倍；没有 vidstab 时退回 deshake（单遍，效果较弱），并在任务里说明。

## 自动用起来

- **自动规则**：“设置 → 自动规则”的动作里可以选一个规整预设，下载完成后按规则自动规整。
- **直播录制**：每个直播间可以设置“录完后自动规整”，选一个预设（默认不开）。
- **媒体库**：多选条目后“批量规整”；单个条目的详情里也有入口。

## 限制和解决办法

清影默认下载的 ffmpeg 是 **LGPL 精简版**：体积小、授权宽松，但没有 x264、vidstab，滤镜也不全。视频规整对此做了检测和兜底，**不装别的东西也能用**，装了完整版会更好：

| 问题 | 精简版下的做法 | 怎么能更好 |
| --- | --- | --- |
| 没有 x264（H.264 软件编码） | 先找硬件编码器（NVENC、QuickSync、AMF、VideoToolbox，**真的试编码 0.3 秒通过**才算可用），再退到 openh264 | “设置 → 组件”里选**完整版（GPL，约 130 MB）**并安装：清影从 BtbN 的构建下载，是你主动点了才下载的，不随安装包分发；也能切回精简版（约 40 MB） |
| 没有 zscale（libzimg）做高质量色调映射 | 程序**内置一张 33×33×33 的 3D LUT**（`.cube`）用 `lut3d` 滤镜做 HDR → SDR，所有 ffmpeg 构建都有这个滤镜 | 完整版有 zscale，走 zscale + tonemap（Hable）。内置 LUT 的结果与它接近，但不完全一样：中间调相差在 10/255 以内，深暗部和肤色的个别通道会有差异 |
| 没有 vidstab（GPL） | 退回 deshake，效果较弱 | 完整版有 vidstab |
| 没有 cropdetect（GPL） | 检测不了黑边，“去黑边”**不生效**：界面上这一项旁边、预览对比和任务说明里都会写明，不会悄悄跳过 | 完整版有 cropdetect |
| 没有 boxblur（GPL） | “用模糊背景补边”（含工具箱的“竖转横”）改用 `gblur`，模糊程度接近 | 完整版有 boxblur |
| 没有 HEVC 编码器 | “省空间（HEVC）”预设会提示不可用，不会静默改成别的编码 | 完整版（libx265）或有硬件 HEVC 编码器 |
| macOS 没有官方的 BtbN 构建 | 无法一键下载完整版 | 用 Homebrew 装 ffmpeg（`brew install ffmpeg`），清影会在常见的 Homebrew 目录里找到它；设置里能看到当前用的是哪个 |

“设置 → 组件”里能看到当前 ffmpeg 的版本、版本类型（精简 / 完整）、能不能做 HDR 转换、LUT、防抖，以及硬件编码器，并给出做不到的事怎么解决。

### 已知的不足

- 硬件编码器的真实使用没有在 NVENC / QuickSync / AMF / VideoToolbox 的机器上测过（开发环境没有这些设备）；试编码失败会自动退回软件编码。
- 完整版下载走的是外部下载地址，没有验证过各个平台上的完整下载流程；下载失败时仍然可以继续使用精简版，所有功能仍然可用，只是上表里的几项会弱一点。
- 内置 LUT 的 HDR → SDR 是近似结果，对画面质量要求高时建议用完整版。
- 自动色阶对已经饱和的彩色画面效果有限。
- 规整只用 ffmpeg，没有 ffprobe：帧率是否可变、黑边、响度都靠 ffmpeg 抽样分析，极端素材（比如前几十秒全是黑场）可能判断不准，可以在界面里手动调整。
