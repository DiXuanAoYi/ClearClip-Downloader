# 浏览器扩展功能规划（1.4 – 1.9）

状态说明：✅ 已有　🟡 部分有　⬜ 计划中　🚫 不做

本文只是规划，**还没有实现任何一项**。每个阶段开工前会再和你确认一次范围。

扩展现状（1.3.2）：右键发送页面 / 链接 / 媒体、嗅探 m3u8 / mpd / 视频 / 音频 / 图片、接管浏览器下载、同步当前网站 Cookie、按住 Alt 绕过接管、未配置时自动打开设置页。

## 一、参考扩展与可借鉴之处

下面是规划时对照的同类扩展。我只把“值得做的行为”写进规划，**没有复制任何代码**；用到的开源项目在动手前会先看许可证（GPL 系的只参考思路，不拷贝实现）。部分扩展的细节来自商店介绍和公开文档，没有逐项在本机实测，标“待实测”的在实现前要先装来试一遍。

### 1. 视频播放控制

| 参考 | 值得借鉴 |
|---|---|
| [Global Speed](https://github.com/polywock/globalSpeed) | 同时控制视频和音频；按网站 / 按标签页 / 全局三层规则；画面里的悬浮控制条；快捷键全部可改；音量增益、音调、跳过静音（待实测）；A-B 循环 |
| [Video Speed Controller](https://github.com/igrigorik/videospeed)（及其 fork） | 页面左上角小面板；`S` / `D` 减速加速，`R` 复位，`Z` / `X` 快退快进，`V` 显隐面板；网站黑名单；“记住上次速度”；输入框里不触发快捷键 |
| Enhancer for YouTube | 影院模式、画面截图、循环、音量增益、自动画质、迷你播放器；偏 YouTube 专用，只取通用的部分 |
| 各浏览器自带的画中画 / 倍速 | 画中画用标准 `requestPictureInPicture()`；Firefox 自带画中画按钮，扩展不重复做 |

可通用的经验：

- 网站会自己改 `playbackRate`（有的在切换清晰度、广告结束时复位），所以要监听 `ratechange` 并在被改回时重新应用。
- 视频常在 iframe 和 Shadow DOM 里，内容脚本要 `all_frames`，并递归进入开放的 Shadow Root。
- 输入框、评论框、在线文档里打字时，快捷键必须让路。
- 用 Web Audio 做音量增益 / 音调会让**跨域且没有 CORS 头**的媒体直接变静音，所以必须是“用户主动打开”，并带自动检测（听不到声音就回退）。

### 2. 图片：放大预览、画廊、批量

| 参考 | 值得借鉴 |
|---|---|
| Imagus | 鼠标悬停缩略图直接显示大图；用“规则”把缩略图地址换成原图地址；规则可自定义和共享 |
| [Picviewer CE+](https://github.com/hoothin/UserScripts/tree/master/Picviewer%20CE%2B) | 悬停浮动工具条；画廊模式看全页图片；旋转、缩放、对比；以图搜图入口；批量保存 |
| [Image Max URL](https://github.com/qsniyg/maxurl) | 站点专用的“取原图”规则库（缩略图 → 原图地址）；做法是规则表，不是通用魔法 |
| Hover Zoom+ | 同 Imagus 一路，轻量；站点覆盖靠规则表 |
| ImageAssistant（图片助手）、Fatkun 批量下载图片 | 全页图片列表；按尺寸、类型、数量筛选；批量打包；这是用户最常用的一类功能 |
| [Search by Image](https://github.com/dessant/search-by-image) | 右键“以图搜图”，一次选多个引擎（Google、Bing、Yandex、TinEye、百度、搜狗等）；支持上传本地图和截取页面区域；可按引擎分组 |

可通用的经验：

- 取原图靠三层：① 页面本身的线索（`srcset`、`data-original`、`<a href="*.jpg">`、`og:image`）；② 通用后缀规则（`_thumb`、`!small`、`?x-oss-process=`、`=w200` 之类）；③ 站点专用规则表。**先做①②，③ 只放少量常见站点并允许用户自定义**，不追求覆盖所有网站。
- 悬停放大必须不干扰点击和拖拽，延迟 150–300 ms 出现，鼠标离开立即消失。
- 以图搜图本质是“把图片地址（或图片内容）交给第三方搜索引擎”，**必须由用户点击触发并明示发给了谁**。

### 3. 解除网页复制 / 右键限制

| 参考 | 值得借鉴 |
|---|---|
| Absolute Enable Right Click & Copy | 在页面主世界里拦截网站对 `contextmenu` / `copy` / `selectstart` 等事件的拦截；覆盖 `onXXX=` 属性写法 |
| SuperCopy 超级复制 | 一键解除选择 / 复制 / 右键限制；按网站开关；复制时去掉网站追加的版权小尾巴 |
| 同类“解除限制”脚本（如各 userscript 站上的复制解锁脚本） | 注入 `user-select: text !important`；捕获阶段吃掉拦截事件 |

可通用的经验：

- 要在 `document_start` 的**页面主世界**里运行（`world: "MAIN"`），才能挡住页面自己注册的监听器和 `oncontextmenu = ...`。Chrome 111+ 支持；Firefox 128+ 支持，需要把 `strict_min_version` 从 121 提到 128，否则退回到注入 `<script>` 元素（会被严格 CSP 挡住，只能尽力）。
- 默认**关闭**，只对用户开启过的网站生效，否则会和一些网站自己的交互（拖拽排序、画板、网页游戏）冲突。
- 网页文库那种把文字画在 canvas 上、或者要登录 / 付费才返回文字的内容，解除限制没有用。**这类不做**（见“不做的”）。

### 4. 其它同类（链接清理、截图、保存网页、二维码）

- [ClearURLs](https://github.com/ClearURLs/Addon)：用规则表删追踪参数（`utm_*`、`fbclid`、`spm` 等），规则表可更新；有重定向链接解包。
- Clean Link / Copy Clean Link 类：复制链接时顺手去追踪参数。
- GoFullPage：整页滚动截图并拼接；注意长页面的画布尺寸上限和固定定位元素重复出现的问题。
- [SingleFile](https://github.com/gildas-lormeau/SingleFile)：把整页内联成一个 HTML；规模大，规划里只做“当前页另存为单文件 HTML”的轻量版，或者直接不做并在文档里推荐它（见功能 8）。
- 二维码类扩展：本地生成二维码，不联网。

## 二、总体设计

### 2.1 目录和模块

```
desktop/extension/
  manifest.json
  background.js          # 只保留路由和右键菜单
  shared.js              # call()、getConfig()、设置读写
  features/              # 新增：每个功能一个文件，各自有开关
    registry.js          # 功能注册表：id、默认值、需要的权限、是否常驻注入
    float-button.js      # 功能 1
    picker.js            # 功能 2、3 的页面内选择 / 总览
    cookie-auto.js       # 功能 4
    progress.js          # 功能 5
    video-control.js     # 功能 6
    read-later.js        # 功能 7
    capture.js           # 功能 8
    clean-link.js        # 功能 9
    qr.js                # 功能 10
    unlock.js            # 功能 11
  ui/                    # 页面内界面：Shadow DOM 里画，不污染网站样式
  vendor/                # 唯一的第三方：QR 生成（小体积、本地）
```

- 页面内的任何界面（悬浮按钮、控制条、放大图、总览网格）都放在**封闭 Shadow DOM** 里，样式不会被网站影响，也不会影响网站。
- 内容脚本分两类：**常驻注入**（视频控制、悬浮按钮、复制解锁）和**按需注入**（总览、截图、选区摘录）。按需的用 `chrome.scripting.executeScript` 配 `activeTab`，不用常驻。
- 每个功能在注册表里有：默认是否开启、需要哪些权限、对页面性能的影响。设置页里按“工具”分组显示开关，**常驻注入类默认关闭**，首次打开时说明它会读取什么。
- 设置存 `storage.local`（本机），不同步到浏览器账号。每网站的规则按主机名存。

### 2.2 权限和商店审核

现状已经有 `<all_urls>`、`webRequest`、`downloads`、`cookies`、`tabs`。新增预计：

| 新权限 | 用于 | 说明 |
|---|---|---|
| `scripting` | 按需注入、注册主世界脚本 | 不新增主机权限 |
| `alarms` | 进度轮询、稍后看提醒 | 无风险 |
| `sidePanel`（可选） | 稍后看 / 总览放侧边栏 | Chrome / Edge 支持，Firefox 用 `sidebar_action`；可以不做，先用弹出页 |
| `clipboardWrite` | 复制清理后的链接 | 可用 `activeTab` 的用户手势代替 |

商店隐私说明要补写的点：

- 常驻注入的内容脚本会运行在所有网页上，但**不上传页面内容**；只有用户点击发送时，URL、标题、（用户选择的）Cookie 才会发给本机的清影。
- 以图搜图会把图片地址交给用户选择的搜索引擎，由用户点击触发。
- 没有任何统计、没有远程规则 / 远程代码；规则表随扩展发布。

### 2.3 应用端要新增或确认的接口

扩展只和本机的清影通信（`127.0.0.1`，令牌 + 设备 ID）。已有：`/api/send`、`/api/grab`、`/api/cookies`、`/api/ping`、`/api/status`、`/api/box`，以及带令牌的 `/api/v1/tasks`（列表）、`/api/v1/tasks/{id}/pause|resume|cancel|remove`、`/api/v1/add`、`/api/v1/library`。

| 功能 | 接口 | 状态 |
|---|---|---|
| 5 进度 | `GET /api/v1/tasks` 轮询（已有）；“打开所在文件夹”缺一个 `POST /api/v1/tasks/{id}/reveal` | 新增一个 |
| 4 自动同步 Cookie | 应用在“需要登录”时需要让扩展知道。方案：`GET /api/v1/login_needed`（返回最近需要登录的站点列表，扩展轮询）；扩展拿到后弹确认再调 `/api/cookies` | 新增一个 |
| 7 稍后看 | 复用 `/api/send` 的“收件箱”；新增一个 `kind: "later"` 标记，应用里“收件箱”能区分 | 小改动 |
| 8 保存网页 | 扩展自己生成文件，经 `/api/send` 以“文件 / 便签”送进应用，或直接用浏览器下载 | 不需要新接口 |
| 2 批量发送 | 复用 `/api/v1/add`（一次多个链接，已支持数组则不改） | 待核实 |
| 其余 | 不需要应用改动 | — |

所有新增接口都沿用现有的“只接受本机 + 已配对设备”的校验，写进 `docs/security-and-privacy.md`。

## 三、十项功能（加一项解除限制）

### 功能 1　视频上的悬浮下载按钮 ⬜

- **做什么**：鼠标移到网页视频上时，角上出现一个小按钮“发送到清影”。单击发送；点右边的小箭头可选清晰度 / 流（用嗅探到的列表）。
- **怎么发**：能嗅探到 m3u8 / mp4 直链就发直链（带 Referer）；是 `blob:` 视频就发页面地址，让 yt-dlp 解析。
- **细节**：只在“尺寸够大（如宽 ≥ 240 px）且正在显示”的视频上出现；广告 / 缩略图小窗不出；全屏时仍可用；站点黑名单；可以改按钮位置（四个角）。
- **性能**：不对每个 `<video>` 常驻监听，使用 `IntersectionObserver` 加鼠标进入事件，只给悬停的那一个挂 UI。
- **风险**：不同网站的覆盖层会盖住按钮（用最高 z-index 的 Shadow DOM 容器 + 跟随视频矩形定位）；一些网站的播放器在 iframe 里（`all_frames`）。
- **默认**：关闭，首次启用说明。

### 功能 2　批量选择并发送 ⬜

- **做什么**：从弹出页或右键进入“选取模式”，页面上所有链接、图片、视频高亮，点选 / 框选多个，一次发送到清影。
- **细节**：框选（拖出矩形）、按住 Shift 连选、按同域名 / 同类型一键全选；右下角显示“已选 12 项”并带“发送 / 取消”；已在下载队列或曾下载过的标灰。
- **和功能 3 的关系**：功能 3 的网格总览里也可以多选，两者共用选择和发送逻辑。
- **风险**：框选与页面自己的拖拽冲突，只在选取模式下接管鼠标，按 `Esc` 退出。

### 功能 3　页面图片 / 视频总览（含图片工具） ⬜

分成五个小项，先后顺序见分期。

| 小项 | 内容 | 参考 |
|---|---|---|
| 3a 总览网格 | 一页看到页面里所有图片 / 视频 / 音频：缩略图、尺寸、类型、大小（有 `Content-Length` 时）；筛选：最小宽高、类型（jpg / png / webp / gif / svg / video）、关键词、去重；多选后下载、复制链接、打包 | ImageAssistant、Fatkun |
| 3b 悬停放大 | 鼠标悬停缩略图显示大图；快捷键：`Alt` 锁定位置、`+ / -` 缩放、`R` 旋转、`S` 保存、`Esc` 关闭；按“取原图”三层规则找大图 | Imagus、Hover Zoom+、Picviewer CE+ |
| 3c 以图搜图 | 右键图片 → 选择搜索引擎（默认 Google、Bing、Yandex、TinEye、百度、搜狗，可自选）；支持多引擎同时打开；图片地址不可公开访问时，扩展取回图片后以 POST 上传到引擎 | Search by Image |
| 3d 画廊模式 | 全屏幻灯片式浏览当前页所有图片，键盘左右切换，幻灯片自动播放，对比两张图 | Picviewer CE+ |
| 3e 取原图规则 | 内置少量常见站点规则（微博、知乎、B 站、小红书、贴吧、Pixiv 缩略图等，具体名单实现时按实测确定）；设置页允许用户自己加“匹配 → 替换”规则 | Image Max URL |

- **下载走向**：选中后可以“发送到清影”（走下载引擎，带 Referer / Cookie，能处理防盗链）或“浏览器直接下载”。
- **隐私**：总览只在用户点击时读取页面里的图片列表，不上传。

### 功能 4　登录状态自动同步 Cookie ⬜

- **现状问题**：清影下载时发现“需要登录”，用户必须手动去扩展里点“同步此网站的登录 Cookie”。
- **做什么**：应用发现“需要登录”时，扩展（后台轮询 `login_needed`）弹一个通知：“XX 网站需要登录才能下载，是否同步浏览器里的登录状态？”确认一次后同步并**自动重试**刚才失败的任务（应用端已有 `retry_after_login`）。
- **UX**：确认弹窗只对每个站点问一次；可以勾选“以后这个网站自动同步，不再询问”（保存在扩展设置，可随时撤销）；同步后弹出结果“已同步 N 条 Cookie，已重新开始 3 个任务”。
- **安全**：只在用户确认后读取该站点的 Cookie；只发给本机的清影；不读取其他站点。
- **关联**：沿用已有的 401 / 403 / 410 → “需要登录”的判断。

### 功能 5　下载进度徽标与弹窗控制 ⬜

- **做什么**：图标上的角标显示进行中的任务数；弹窗里新增“下载”标签：列出进行中和最近完成的任务，进度条、速度、剩余时间，单个 **暂停 / 继续 / 取消 / 打开所在文件夹**，全部暂停 / 全部继续。
- **轮询策略**：弹窗打开时 1 秒一次，关闭后后台每 10 秒一次（`alarms`），应用没运行时静默退避，不弹错误。
- **细节**：任务完成时给一次通知（可关）；点通知打开文件夹。
- **应用端**：需要新增 `reveal`（见 2.3），其余已有。

### 功能 6　视频播放增强 ⬜

作为独立的“播放工具”，页面上只出现一个可收起的小控制条（默认透明度低，悬停显现），所有功能可单独开关。

| 小项 | 说明 | 备注 |
|---|---|---|
| 6a 倍速 | 0.1× – 16×，快捷键加减 0.1 / 0.25（可改），按键复位；预设 0.5 / 1 / 1.25 / 1.5 / 2 / 3；对 `<audio>` 也生效 | 监听 `ratechange` 防网站改回；保持音调 `preservesPitch` |
| 6b 记住每个网站的倍速 | 以主机名为键记住上次倍速；可设“新视频默认倍速”；可按网站黑名单 | 数据在 `storage.local` |
| 6c 快进快退 / 逐帧 | 快捷键 ±5 / 10 / 30 秒；`,` `.` 逐帧（按 1/30 秒近似） | 暂停时才逐帧 |
| 6d 画面截图 | 把当前帧存成 PNG / JPG，复制到剪贴板或发送到清影的图库 | 跨域且无 CORS 的视频画布会被污染，回退成 `tabs.captureVisibleTab` 裁剪当前可见区域 |
| 6e 画中画 | 一键 `requestPictureInPicture()` | Firefox 自带，不重复做；检测不到则隐藏按钮 |
| 6f A-B 循环 / 整段循环 | 标记 A 点和 B 点反复播放 | 数据不持久，随页面 |
| 6g 跳过片头 / 片尾 | 用户给某网站设“开头跳过 N 秒”“结尾提前 N 秒切下一集”；**只用固定秒数，不做自动识别** | 避免误判，也避免引入模型 |
| 6h 音量增益 | 超过 100% 的放大（最高 400%），可选 | 用 Web Audio；跨域无 CORS 视频会变静音，检测到就自动撤销并提示 |
| 6i 画面调整 | 镜像、旋转、亮度 / 对比度 / 饱和度、缩放填充 | 用 CSS `filter` / `transform`，不改播放器 |
| 6j 快捷键面板 | 全部快捷键可改，冲突提示；输入框内不触发 | 默认按键尽量避开网站常用键（空格、方向键不抢） |

- **兼容**：站点把视频放进 closed Shadow DOM 时拿不到，会提示“该网站暂不支持”；MSE / `blob:` 视频的 `playbackRate` 仍可改。
- **性能**：只在检测到 `<video>` / `<audio>` 的页面才初始化，用 `MutationObserver` 带去抖监视新增元素。
- **默认**：6a / 6b / 6c 默认开启（对页面几乎无影响），其余需要在设置里打开。

### 功能 7　稍后看 / 收件箱联动 ⬜

- **做什么**：右键或快捷键“稍后看”，把当前页或链接存进清影的**收件箱**（带标题、封面、时间），不立刻下载；弹窗里有“稍后看”标签，可一键下载、删除、标记已看。
- **好处**：和手机发链接、剪贴板监听共用同一个收件箱，不用另建一套。
- **细节**：同一链接去重；离线时存在扩展本地，应用上线后补发；“稍后看”到期提醒默认关。
- **应用端**：`/api/send` 加一个 `kind: "later"`；应用内收件箱加一个来源标记。

### 功能 8　页面保存与摘录 ⬜

| 小项 | 说明 |
|---|---|
| 8a 选中文字摘录 | 选中后右键“摘录到清影”：保存选区文字 + 来源链接 + 标题到应用的“文字便签”（走已有的 `receive_note`） |
| 8b 整页截图 | 当前可见区域 / 选区 / 整页；整页用滚动拼接，处理固定头部重复、超长页面分块；保存 PNG 或发送到清影 |
| 8c 另存为 PDF | 调用浏览器的打印为 PDF（`window.print()`/`tabs.saveAsPDF` 视浏览器）；Firefox 有 `tabs.saveAsPDF`，Chrome 走打印对话框 |
| 8d 保存为 Markdown | 用阅读模式式的正文提取（找 `<article>`、段落密度）转成 Markdown，带图片链接；提取不准时让用户先选区再保存 |
| 8e 单文件 HTML | 当前页内联成一个 HTML。工作量大、容易出错，**先不做**，设置页里放“推荐使用 SingleFile”的说明 |

- **风险**：正文提取的准确率在不同网站差别很大，8d 标为“尽力而为”；整页截图在超长页面（> 16384 px）要分块拼接。

### 功能 9　链接清理（去追踪参数） ⬜

- **做什么**：① 右键“复制干净的链接”；② 发送到清影之前自动去掉追踪参数；③ 可选：在地址栏里自动清理（需要 `declarativeNetRequest` 重定向，**默认不做**）。
- **规则**：内置一份小规则表（`utm_*`、`fbclid`、`gclid`、`spm`、`from`、`share_*` 等，具体按实测维护），按域名分组；保留对功能必需的参数（如视频 `v=`、`t=`），白名单优先；用户可自定义。
- **重定向解包**：常见跳转链接（如 `?url=` / `target=` 的外链中转）解出真实地址。
- **测试**：规则表做成纯函数，写表驱动单元测试（输入输出对照）。

### 功能 10　二维码 / 发送到手机 ⬜

- **做什么**：弹窗里“二维码”：当前页链接（或选中的文字、图片地址）生成二维码，手机扫码打开。
- **本地生成**，不请求任何网络服务；使用一个小体积的开源 QR 库放进 `vendor/`（许可证要宽松，如 MIT）。
- **发送到手机**：另一入口——把当前页链接放进清影的“电脑发给手机”盒子（`/api/box` 对应的发送方向）；手机网页打开时能看到并一键打开 / 下载。需要先确认应用端已有从扩展写入“发给手机”的入口，没有就新增（小）。

### 功能 11　解除网页复制 / 右键限制（来自你这次的补充）⬜

- **做什么**：对开启的网站，解除“禁止选中 / 复制 / 右键 / 拖拽 / 快捷键”，并去掉复制时网站追加的版权小尾巴。
- **做法**（组合）：
  1. 注入样式：`* { user-select: text !important; -webkit-user-select: text !important }`，处理 `user-select: none`；
  2. 主世界脚本：在捕获阶段拦截并放行 `contextmenu`、`copy`、`cut`、`paste`、`selectstart`、`dragstart`、`mousedown`、`keydown`（只放行 `Ctrl+C / A / X / V / S / P / U / F12`）；清除 `document.oncontextmenu` / `onselectstart` / `oncopy` 等属性处理器；包装 `addEventListener`，对上述事件的“阻止默认”调用无效化；
  3. 复制尾巴：监听 `copy`，如果网站改写了剪贴板内容，用 `getSelection().toString()` 重新写回；
  4. 弹窗里给一个开关“解除此网站的限制”，可选“仅这次 / 总是”，总是时加入站点名单。
- **默认**：关闭，**只对用户开启的网站生效**；设置里有“全站默认开启”的高级选项，但会有提示。
- **兼容**：拖拽排序、画板、网页游戏、在线表格会被影响——所以默认不全站开；开启后出问题可一键“对此网站关闭”。
- **对 Firefox**：`world: "MAIN"` 需要 128+，旧版本回退到注入 `<script>`（严格 CSP 的网站无效，只做“尽力”）。
- **边界**：只解除“浏览器端的限制”，**不绕过付费墙、登录墙，也不提取 canvas / 图片里的文字，不破解 DRM**。

## 四、分期

每期独立发一个扩展版本，应用端有改动的同时发应用版本。

| 期 | 扩展版本 | 内容 | 为什么先做 |
|---|---|---|---|
| A 基础 | 1.4 | 功能注册表 / 设置页“工具”分组；**9 链接清理、10 二维码、5 进度与弹窗控制、4 自动同步 Cookie** | 风险最低，不需要常驻注入，也直接解决已发生的“要手动同步 Cookie”的问题；应用端只加 `reveal` 和 `login_needed` |
| B 页面选取 | 1.5 | **1 悬浮下载按钮、2 批量发送、3a 总览网格、3c 以图搜图** | 都是“用户在页面上点”的功能，价值最直接；开始需要常驻或按需注入 |
| C 图片增强 | 1.6 | **3b 悬停放大、3d 画廊、3e 取原图规则** | 规则表和性能调优工作量大，放在 B 之后，等总览网格稳定再做 |
| D 播放增强 | 1.7 | **6a – 6j 视频播放控制**（先 6a/6b/6c/6d/6e，再 6f–6j） | 对页面影响最大（常驻注入、快捷键、音频），需要最多兼容性测试，独立一期 |
| E 收集与保存 | 1.8 | **7 稍后看、8a / 8b / 8c / 8d 页面保存与摘录** | 依赖应用端收件箱的小改动 |
| F 解除限制 | 1.9 | **11 解除复制 / 右键限制** | 需要主世界脚本、权限说明最多，且最容易被误解，放最后，并单独写隐私说明 |

每期都要更新：扩展 `README.md`、`docs/` 对应说明、商店隐私说明、`CHANGELOG`。

## 五、测试

- **纯函数单测**（`node --test`，不用浏览器）：链接清理规则表、取原图规则、倍速记忆 / 站点匹配、文件名清理、选区去重。
- **内容脚本集成测试**：用仓库已有的 Playwright（本机预装 Chromium）加载解压后的扩展，跑一个本地测试页：有 `<video>`、`<img srcset>`、禁用右键 / 复制的页面、iframe 里的视频、Shadow DOM 里的视频。检查：悬浮按钮出现 / 消失、倍速被网站改回后恢复、解除限制后 `contextmenu` 未被拦截、总览能列出全部图片。
- **与应用联调**：起一个假的本机服务器（模拟 `/api/v1/tasks`、`/api/cookies`、`login_needed`），验证扩展的轮询、退避、确认流程。真实应用的端到端由你本机装好后验证。
- **兼容性清单**：Chrome、Edge、Firefox 各过一遍；Firefox 单独验证 `world: "MAIN"` 和画中画的行为。
- **性能基线**：在一个有 500 张图的页面上，打开总览不卡 UI；常驻功能开启后，空白页内存和 CPU 无明显增加（用 Playwright 的 trace 简单对比）。

## 六、风险与取舍

- **商店审核**：权限越多审核越严。新增权限只有 `scripting` / `alarms`，主机权限不变，但“所有网页常驻注入”需要在说明里解释清楚；解除限制放最后一期，若审核有问题可以拆成独立扩展。
- **网站兼容**：播放器、图片懒加载、防盗链、Shadow DOM 都会让个别网站失效。策略是：**通用做法 + 站点黑名单 + 用户可一键对当前网站关闭**，不为单个网站写大量特例。
- **规则维护**：取原图规则和追踪参数规则会过时。规则表放在随扩展发布的 JSON 里，扩展更新时一并更新；**不做远程下发**（避免远程代码和隐私问题）。
- **Manifest V3 限制**：后台是会休眠的 service worker，轮询用 `alarms`，状态落在 `storage`，不依赖内存变量。Firefox 的 MV3 允许 `background.scripts`，现在已兼容。
- **性能**：常驻脚本必须“无事不做”；所有观察器要去抖，不在不含视频 / 图片的页面做任何工作。
- **隐私**：不读取页面内容上传；不加统计；Cookie 只在用户确认后读取；以图搜图只在点击后把图片地址交给所选引擎。

## 七、不做的

- 绕过付费墙、登录墙、DRM，或提取 canvas / 图片中的文字（网页文库一类）。
- 远程下发规则或脚本；任何形式的统计上报。
- 自动识别片头 / 片尾（需要模型，误判成本高）。
- 内置完整的网页另存（SingleFile 已经做得很好，只在设置页推荐）。
- 破解网站的防盗链之外的访问控制；只做用户自己浏览器已经能看到的内容。
