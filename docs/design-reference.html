清影：短视频解析桌面版规划

做成一个独立运行的短视频解析与下载桌面程序。本页包含：起点、15 个同类产品调研、5 张界面参考图、技术选型和分阶段实施计划。本阶段只做规划，不改动现有代码。

起点竞品调研设计参考图技术选型实施计划风险

1. 起点

项目最初只是一个很小的抖音、快手解析接口。桌面版的解析层是用 Rust 重新实现的，每个平台一个独立模块。仓库不再包含最初的网页和 PHP 代码。

2. 同类产品调研（15 个）

覆盖三类：专做抖音/快手/小红书的开源工具、通用视频下载器（多为 yt-dlp 前端）、商业下载软件。重点看形态、技术栈和可借鉴的交互。

调研结论

主流程只有一步4K Video Downloader、Cobalt、TikDown 都把"粘贴"做成唯一动作。我们也应支持剪贴板监听，复制分享文案后自动识别。
Tauri 已是这一类工具的常见选择05、08、09 都用 Tauri，安装包体积远小于 Electron，适合工具型软件。
队列和历史是标配02、10 都有并行下载、重试、去重。单次解析的网页形态只覆盖了最基础的场景。
Cookie 管理决定可用性01、04 都为 Cookie 单独做了工具。桌面端可以内置一个登录窗口获取 Cookie，比网页版更有优势。
解析层要可插拔平台接口变动频繁，01、03 都把每个平台写成独立模块，方便单独修复和热更新规则。
合规提示要放在显眼处开源项目普遍声明"仅供学习"。桌面版应在首次启动时展示免责声明，只下载用户有权保存的内容。

4. 技术选型

方案安装包复用现有代码解析逻辑放哪结论
Tauri 2 + Vue 3 + Rust约 10 MB前端交互可迁移到 Vue 3；解析逻辑用 Rust 重新实现Rust（reqwest），不受浏览器跨域限制推荐
Electron + Vue 3 + Node100 MB 以上同上，解析移植到 TypeScriptNode 主进程可行，开发快，但体积和内存偏大
Wails（Go）/ Flutter10–25 MB前端需重写Go / Dart团队无相关积累时不划算

推荐技术栈

  • 壳：Tauri 2，插件 clipboard-manager、notification、global-shortcut、dialog、updater、sql（SQLite）、系统托盘。
  • 前端：Vue 3 + TypeScript + Vite + Pinia，组件库用 Element Plus（与现有 Element UI 用法相近，迁移成本低）。
  • 解析层：Rust，定义统一的 Provider trait（matches(url) / resolve(url) → MediaInfo），每个平台一个文件；输出结构沿用现有 nickname / video_url / music / type 并补充封面、作者、时长、分辨率。
  • 下载器：Rust 流式下载，带 Referer/UA，按事件把进度推给前端；支持并发数、断点续传、失败重试。
  • 可选：ffmpeg 侧车，用于图集合成视频、音视频分离。

5. 实施计划

按 1 名全栈开发估算，共约 6 周。每个阶段结束都有可演示的产物。

P0 · 第 1 周

技术验证

  • 搭 Tauri 2 + Vue 3 空壳，三平台本地能跑起来
  • 验证抖音、快手当前可用的取数方式（分享页内嵌 JSON / 新接口及签名），确定是否需要 Cookie
  • 用 Rust 写出最小的抖音解析并通过命令返回给前端
完成标准：粘贴一条抖音链接，桌面窗口里拿到无水印直链。若取数方式不可行，在这里决定是否改为"远程 API 为主"。
P1 · 第 2–3 周

MVP

  • 移植抖音、快手的视频与图集解析，处理图集和错误码
  • 解析主页（参考图 A）、单任务下载、预览
  • 从分享文案中提取链接；支持远程 API 模式
  • 解析逻辑的单元测试（用录制的响应样本，不依赖线上）
完成标准：两个平台四种内容都能解析并下载到本地。
P2 · 第 4–5 周

效率功能

  • 下载队列（参考图 B）：并发、暂停、重试、直链过期自动重新解析
  • 图集选择（参考图 C）、音乐/封面单独下载
  • 剪贴板监听、托盘迷你窗、全局快捷键（参考图 E）
  • SQLite 历史记录与去重、媒体库页；设置页（参考图 D）
  • 内置登录窗口获取 Cookie，存系统钥匙串
完成标准：连续复制 10 条链接，全部自动进队列并下载完成。
P3 · 第 6 周

打包与发布

  • GitHub Actions 矩阵构建 Windows（msi/nsis）、macOS（dmg，Intel + Apple Silicon）、Linux（AppImage/deb）
  • 代码签名与 macOS 公证；自动更新
  • 首次启动免责声明、README 更新
完成标准：从 Releases 下载安装包，三平台安装即用并能收到更新。
P4 · 之后

扩展

  • 新增平台：小红书、B站、微博等（依赖 Cookie 的平台走内置登录）
  • 解析规则远程下发，平台接口变化时不必发新版
  • 图集合成视频（ffmpeg）、批量导入链接文件

6. 风险与对策

风险影响对策
平台接口和签名频繁变化解析失效，用户直接感知Provider 独立模块 + 规则远程更新 + 远程 API 备用通道；用样本测试快速定位
风控（需要 Cookie、验证码）部分内容无法获取内置登录窗口；请求频率限制；失败时给出明确提示
直链有时效排队后下载 403下载前检查，过期自动重新解析
版权与合规分发渠道下架、法律风险首次启动声明，仅用于个人有权保存的内容；批量采集他人主页等功能默认关闭
macOS 签名/公证成本未签名包被系统拦截P3 预留 Apple 开发者账号；早期可先发 Windows 版
