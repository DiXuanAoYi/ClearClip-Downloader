# 下载引擎（0.8.0）

这一页说明普通 HTTP(S) 文件下载的几项增强。规划见 [roadmap.md](roadmap.md)。

## 哈希校验

在链接里写上期望的哈希，下载完成后会流式计算（不整文件读进内存），不一致就删除文件并重下一次，仍不一致则报错：

```
https://example.com/app.zip#sha256=<64 位十六进制>
https://example.com/app.iso#checksum=md5:<32 位十六进制>
https://example.com/app.iso?sha1=<40 位十六进制>
```

支持 MD5、SHA-1、SHA-256、SHA-512；片段（`#`）和查询参数（`?`）都行。本机接口 `/api/grab` 也可以直接给 `checksum` 字段（`sha256:…` 或纯十六进制，按长度判断）。多文件的任务（音视频分开下载再合并）暂不校验。

## 备用地址（镜像）

同一个文件有多个下载地址时，在链接后追加 `#mirror=<编码后的地址>`（可重复，最多 8 个），或在 `/api/grab` 的 `mirrors` 字段给出。主地址失败（重试用尽、404 等）时按顺序换到下一个地址，已下载的部分按服务器校验信息决定能否继续。

## 分段数与自动降级

- 分段数 1–64（“设置 → 下载”），默认 4。每段至少 1 MB。
- 服务器不支持 Range 时自动降为单线程，并按域名记住 7 天，之后不再重复探测。
- 服务器因并发连接过多拒绝（429 / 503 / 连接被重置）时，会自动减少连接数继续下载，并把该域名可用的连接数记住 30 天。记录保存在数据目录的 `host_limits.json`，可以直接删除。
- 失败会按设置的次数和间隔指数退避重试；403 / 404 / 410 会重新解析下载地址。

## 边下边播

下载队列里，正在下载或已暂停的**单个 HTTP 音视频文件**会出现“边下边播”按钮，在内置播放器里播放已经下载的部分。

- 分段下载时只能播放从文件开头起连续下好的部分；拖到还没下载到的位置会等待（最多 45 秒），下载追上后继续播放。
- MP4 的索引（moov）在文件末尾时，要下载到末尾才能开始播放；这类文件建议等下载完成。
- m3u8 / mpd 等分片格式、站点解析出的流、音视频分开下载的任务不支持边下边播。
- 播放用的是只监听本机回环地址的临时服务，地址带随机令牌，关闭播放器后失效。

## 代理

“设置 → 网络”里可以添加自定义代理，并按网站分流（直连 / 系统代理 / 某个自定义代理）。

- 支持 `http://`、`https://`、`socks5://`、`socks5h://`，用户名密码写在地址里。
- `socks5://` 在本机解析域名；要让代理端解析（避免 DNS 污染）请用 `socks5h://`。
- 代理对 HTTP(S) 下载、站点解析、m3u8 生效；FTP / SFTP / BT / ed2k 和交给 ffmpeg 的流暂不走代理。

## 完成后动作

“设置 → 下载”里可以设置队列全部完成后关机、休眠、退出或运行命令（原有功能，0.8.0 未改动）。
