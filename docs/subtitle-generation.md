# 给没有字幕的视频加字幕：设计规划（字幕工坊）

状态：**设计稿，尚未实现**。实现前请先确认文末“需要你决定的事”。

## 1. 现状：已经有什么、缺什么

| 环节 | 现状 | 缺口 |
| --- | --- | --- |
| 语音识别 | `ai.rs`：本机 whisper.cpp（`-osrt`）或 OpenAI 兼容接口，云端按 10 分钟切段 | 只有**句子级**时间戳；没有 VAD（静音处会幻觉、重复）；没有词级时间戳，无法自己重新断句；没有识别质量检查 |
| 断句 | 直接用 whisper 的段 | 长句、半句、中英文混排都不处理，字幕一屏太长或太碎 |
| 校对 | 无 | 同音字、专有名词、口头禅、标点 |
| 翻译 | `map_cues_g`：批量、术语库、AI 专家、模型池 | 没有“只翻译缺的语言”“整段上下文”“译文长度约束”“失败行单独重译” |
| 双语 | `subtitle_tools::merge_bilingual`（只在工具箱里有） | 没有统一的双语显示模型；播放器 / 扩展里没有开关 |
| 下载 / 导出 | SRT、VTT、ASS | LRC、TXT、JSON（带词时间戳）、双语排版、单语分文件 |
| 合成 | `postprocess::burn_subtitles`、软字幕内嵌 | 烧录样式固定；竖屏 / 横屏不自适应；没有样式预设 |
| 编辑 | 无 | 没有可视化校对、拆分合并、整体平移、逐行重译 |
| 入口 | 工具箱 → AI 里单独转写；扩展里“用清影转写” | 解析页、下载队列、媒体库、播放器、批量、订阅都没有“生成字幕”入口；下载完没有字幕时不会自动补 |

## 3. 总体设计

### 3.1 一条可恢复的流水线（“字幕工坊”任务）

```
素材(本地文件 / 媒体库 / 链接) 
  → ① 取音频（ffmpeg，单声道 16k；可选：人声分离 / 降噪）
  → ② VAD 切出有人声的片段（静音不送识别）
  → ③ 识别（本机 whisper.cpp 或云端接口），拿到词级时间戳
  → ④ 断句（规则：标点 / 停顿 / 字数；可选：LLM 按语义）
  → ⑤ 校对（可选，LLM：同音字、专有名词、口头禅、标点；带术语库与 AI 专家）
  → ⑥ 翻译（可选，可同时多个目标语言；带上下文）
  → ⑦ 双语合成、导出
  → ⑧ 软字幕内嵌 / 硬字幕烧录（可选）
  → 登记到媒体库，播放器自动加载
```

- 每一步的结果写进缓存（键：音频指纹 + 该步骤的参数），改了后面的参数只重跑后面的步骤；中途取消 / 崩溃后可从断点继续。
- 每一步之后可以选择“**暂停等我校对**”（参考 pyVideoTrans），默认不暂停。
- 云端识别和云端翻译都会把内容发给第三方：流程开始前显示一次性提示；本机识别永远可选，且是默认推荐。

### 3.2 数据模型：字幕轨（Track）

```
Track { id, mediaId, lang, kind: asr | human | machine-translation | imported,
        cues: [{ start, end, text, words?: [{t0,t1,w,conf}], speaker?, srcIdx? }],
        sourceTrackId?  // 译文指向它的原文轨，逐行对应
        params, createdAt }
```

- 译文轨与原文轨**逐行对应**（`srcIdx`），所以“双语”不是另一份文件，而是**显示方式**：
  `仅原文 | 仅译文 | 双语（原文在上）| 双语（译文在上）`。
- 导出和播放时再按显示方式合成，因此双语开关在应用、播放器、浏览器扩展里是同一个概念、同一套数据。
- 一个视频可以有多条译文轨（英→中、英→日），互不影响。

### 3.3 识别

- 引擎（可在设置里按“模型池”思路配置，失败自动换下一个）：
  1. 本机 whisper.cpp（已有；增加模型管理：tiny / base / small / medium / large-v3-turbo，量化版，下载 / 删除 / 显示大小与速度预估；GPU 可用时自动启用）。
  2. 云端 OpenAI 兼容接口（已有）。增加免费额度较多的入口作为预设：Groq（whisper-large-v3-turbo）、硅基流动（SenseVoice / Whisper 类），与 AI 模型池一样可轮换。
  3. 不接入未公开的第三方“免费识别”接口。
- **VAD**：优先用 whisper.cpp 自带的 VAD；云端引擎则先在本机用 ffmpeg `silencedetect` 或内置 Silero（`tract-onnx` 已在项目中）切段，只上传有人声的部分，也降低费用。
- **防幻觉**：丢弃“字幕由…提供”“谢谢观看”这类常见幻觉；重复内容折叠；低置信度且极短的段落标记；检测到整段重复循环时降低温度重试一次。
- **语言**：自动检测 + 手动指定；多语混合视频允许按片段指定（后续）。
- **词级时间戳**：本机引擎直接取；云端接口支持 `timestamp_granularities=word` 时取，不支持时降级为句级并在任务里说明（断句只能按句内字数平均切）。

### 3.4 断句与排版（体验差异最大的一步）

- 规则断句：句末标点必断；逗号等在超长时断；两词间停顿 > 阈值时断；单行上限按语言（中日约 20 字，英文约 42 字符），最多 2 行；最短显示时长 / 最长显示时长；相邻字幕间隙小于阈值时对齐，避免闪烁。
- 语义断句（可选，LLM）：把词序列分成语义完整的行，输出必须与输入逐词一致（程序校验，不一致则回退规则断句），参考 VideoCaptioner。
- 竖屏视频自动用更短的行宽和更靠上的位置。

### 3.5 校对（可选）

- LLM 逐批处理，只允许**改字，不改时间、不增删行**（程序校验行数一致）；带术语库、AI 专家、视频标题 / 简介 / 频道名作为上下文。
- 每一行保留“改前 / 改后”，编辑器里可逐行还原。
- 同时提供不用 LLM 的清理：去口头禅 / 语气词、去重复词、全半角与标点统一（`subtitle_tools::clean` 基础上扩展）。

### 3.6 翻译

- 复用现有 `map_cues_g` + AI 模型池 + 术语库 + AI 专家，补充：
  - 以**整段上下文**（前后各若干行）翻译，避免孤立行翻错；
  - 译文长度约束（不超过原文行宽的约 1.3 倍，超出自动让模型缩写重译）；
  - 逐行失败 / 为空 / 与原文一致时只重译这些行；
  - 多目标语言并行；
  - 翻译缓存按（原文 + 目标语言 + 专家 + 术语库版本）计算，换专家或术语库不会再命中旧译文（顺带修复现有缓存的这个缺口）。
- 可选“反思”模式：翻译后让模型自查并改进（参考 VideoCaptioner），默认关闭，费用约翻倍。
- 对**已经有字幕**的视频：直接翻译已有字幕，不重新识别。

### 3.7 输出与下载

- 格式：SRT、VTT、ASS（含样式）、LRC（歌词 / 播客）、TXT（纯文稿，可带时间）、JSON（带词级时间戳，给剪辑 / 文稿剪辑用）。
- 内容：原文 / 译文 / 双语（单文件）/ 双语拆成两个文件；文件名 `视频名.语言.srt`，和视频放一起，播放器自动加载（已有约定）。
- 软字幕：多条字幕轨（原文、各译文、双语）一次内嵌，不重新编码；MP4 用 `mov_text`，MKV 用 SRT/ASS。
- 硬字幕：样式预设（字体、字号、描边 / 阴影 / 底框、位置、双语两行不同大小和颜色）；横竖屏自适应安全边距；预览一帧再决定；需要重新编码，沿用已有的进度和硬件编码设置。
- 卡拉 OK 式逐词高亮（ASS `\k`）作为可选样式，靠词级时间戳实现。

### 3.8 编辑器（校对界面）

- 表格：序号 / 开始 / 结束 / 原文 / 译文 / 状态（已改、低置信度、过长、重叠）；与内置播放器联动（点行跳转、播放时高亮当前行、循环播放当前行）。
- 操作：改文字、拆分、合并、调整起止、整体平移 / 缩放（已有工具）、查找替换、逐行重新识别 / 重新翻译、撤销重做。
- 低置信度词用颜色标出（词级置信度来自 whisper）。
- 波形放第二期。

### 3.9 入口（让用户“顺手就能用”）

1. **解析页 / 下载队列**：视频没有字幕时，字幕区显示“没有字幕 → 用 AI 生成”；下载完成的条目右键“生成字幕”。
2. **设置 → 解析 → 字幕**：新增“**下载后没有字幕时自动生成**”（默认关闭）、默认识别引擎 / 模型、默认目标语言、默认是否双语、是否自动内嵌；对批量、订阅、剪贴板自动下载都生效。
3. **媒体库**：条目详情里有“字幕”标签页，列出所有字幕轨，可生成 / 翻译 / 编辑 / 导出 / 删除。
4. **内置播放器**：字幕菜单选轨、双语开关（四种显示方式）、字号、位置、延迟微调。
5. **工具箱 → 字幕**：保留现有工具，并加入“生成字幕”的完整流程面板（拖入文件即可用）。
6. **浏览器扩展**：
   - 摘要面板已有“用清影转写”；增加“在页面视频上显示字幕”：把生成好的字幕叠在任意网页视频上，有双语开关、字号 / 位置 / 延迟、导出；
   - 译文先出，原文识别结果可流式刷新（后续）。
7. **CLI / HTTP API**：`clearclip subtitle generate <文件或链接> --lang auto --translate zh --bilingual --burn`，方便自动化与规则引擎（“下载完成且无字幕 → 生成字幕”）。

## 4. 分期

| 期 | 内容 | 价值 |
| --- | --- | --- |
| **S1 核心** | 字幕轨数据模型；VAD + 词级时间戳；规则断句；防幻觉；缓存与断点续跑；翻译补强（上下文、长度约束、失败重译、缓存键）；双语显示模型与导出（SRT/VTT/ASS/LRC/TXT/JSON）；工具箱“生成字幕”面板；下载后自动生成设置；CLI/API | 最基础、最缺的“无字幕 → 有字幕（含双语、翻译、下载）” |
| **S2 体验** | 字幕编辑器；媒体库字幕标签页；播放器双语开关；软字幕多轨内嵌；硬字幕样式预设与预览；解析页 / 队列入口；识别模型管理（下载 / 删除 / GPU） | 可校对、可看、可烧录 |
| **S3 扩展与云端** | 浏览器扩展页面字幕层（双语开关、样式、延迟、导出）；云端识别预设（Groq / 硅基）并入模型池轮换；语义断句；LLM 校对；反思翻译 | 在任意网站看 |
| **S4 进阶（可选组件）** | 说话人区分；人声分离后识别（已有人声分离模型）；逐词卡拉 OK 样式；波形；多语混合 | 播客、访谈、歌曲 |

## 5. 测试与验证

- 纯逻辑单元测试：断句（中英日、标点、停顿、竖屏）、幻觉过滤、双语合成四种方式、轨道对齐、缓存键、行数校验。
- 假引擎集成测试：用脚本替代 whisper-cli / HTTP 接口，覆盖取消、断点续跑、云端失败转下一个引擎、翻译失败行重译。
- 真实媒体：用 ffmpeg 合成的静音 + 音调样本验证 VAD 切段和时间戳对齐；真实语音只能在有 whisper 模型的环境验证，会在报告里明确哪些没有实测。
- 烧录 / 内嵌：沿用 `postprocess` 现有测试，增加双语 ASS 与竖屏样例。
- 扩展：沿用 `e2e/ext-real.cjs` 在真实 Chromium 里验证字幕层（含双语切换）。

## 6. 风险与取舍

- 本机识别速度取决于设备；低配机器默认推荐 base / small 量化，并显示预计耗时。
- 云端接口对词级时间戳的支持不一致，已设计降级路径。
- LLM 校对 / 翻译有费用与隐私问题；默认关闭校对，翻译沿用现有设置，流程开始前提示。
- 参考项目多为 GPL：只借鉴流程和思路，不复制代码；依赖的 whisper.cpp、Silero 均为 MIT。

## 7. 需要你决定的事

1. **默认识别引擎**：推荐“本机 whisper.cpp（small 量化）为默认，云端为可选”，是否同意？
2. **免费云端识别**：推荐只接 Groq / 硅基这类有公开 API 和免费额度的；不接必剪 / 剪映这类未公开接口，是否同意？
3. **实现顺序**：推荐先做 S1，再做 S2；扩展里的字幕层（S3）是否要提前到 S2 之前？
4. **自动生成默认关闭**：“下载后没有字幕自动生成”默认关闭（会占用算力 / 产生费用），是否同意？
