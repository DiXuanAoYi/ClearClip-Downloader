# 功能规划：通用下载器路线图

清影已经是一个通用下载器（yt-dlp 通用引擎、HLS / DASH、专用站点插件、剪辑与视频规整工具）。这份规划参照常见下载器（IDM、Motrix、Gopeed、aria2 系等）的能力，补上协议、手机互传、浏览器接管等缺口。

状态说明：✅ 已有　🟡 部分有　⬜ 计划中　🚫 不做

## 二、阶段 1：手机与电脑互传（0.6.0）

目标：做成简洁的“隔空投送”式收发，不依赖任何外部服务器，只在局域网内传输。

**手机 → 电脑**
- 手机网页可以选择多个文件（文本、图片、视频、压缩包、任意文件），也支持拖拽（用电脑浏览器打开时）。每个文件有真实的上传进度条。
- 文件流式写入电脑磁盘（先写 `.part`，写完再改名），不整文件读进内存。写入前检查磁盘剩余空间，超过大小上限会被拒绝。
- 保存到“接收文件夹”（可在设置里改），文件名做规范化并避免重名。电脑上有“收到的文件”列表：打开、在文件夹中显示、复制路径、删除、导入媒体库。
- 自动识别：发来的文字里有链接就按原有流程下载；没有链接就存为文字便签。
- 压缩包可选自动解压（默认关闭），解压时防路径穿越，限制总大小和文件数。绝不自动运行任何收到的文件。

**电脑 → 手机**
- 电脑上点“发送到手机”，或把文件 / 文本拖进窗口：文本、图片、视频、压缩包、任意文件，可多选。
- 手机网页的“电脑发来的”列表里点开即下载。服务端按块从磁盘读取并发送，支持 Range（断点续传、视频拖动），大文件不进内存。
- 电脑上每个文件显示发送进度条（已发送字节数 / 总大小）和下载次数；手机网页同样显示进度。
- 可设置过期时间（默认 24 小时）；可随时撤回。

**安全**：沿用访问令牌加配对确认；只接受局域网地址；单文件大小上限（默认 4 GB，可改，0 为不限制）；同时传输数量限制；不暴露电脑上的任何其他文件，只能下载用户明确添加的项目。

## 三、阶段 2：浏览器扩展（0.6.1）✅

- **接管下载**：用 `downloads` 权限接管普通下载，有站点白名单 / 黑名单、按大小和类型过滤，按住 Alt 点击或弹窗里“暂停 30 分钟”可以绕过；接管时带上 Cookie、Referer 和文件名。默认关闭，由用户在扩展设置里打开。清影没接住时自动交还给浏览器，弹窗里保留最近接管的记录。清影端新增“文件”资源类型和本机接口 `POST /api/grab`。
- **嗅探增强**：在 m3u8 和视频、音频文件之外，增加 mpd（DASH）和图片；去重，按清晰度和大小排序；显示预估大小和时长；支持批量勾选发送。
- **右键菜单**：对网页、链接、图片、音视频元素直接“用清影下载”。
- 说明：嗅探不了 DRM 加密内容（弹窗里会标出），已写入扩展说明。
- 已知限制：接管的下载由清影重新请求，一次性链接、POST 表单下载可能失败（可以改用浏览器重新下载）；真实浏览器里的接管流程需要在 Chrome / Edge / Firefox 上手工验证。

## 四、阶段 3：协议扩展（0.7.0，已完成）

完成情况和已知限制见 [protocols.md](protocols.md)。

| 协议 | 做法 |
|---|---|
| FTP / SFTP | Rust 库（suppaftp、russh），复用现有分片与续传 |
| thunder:// 等 | 解码成普通链接后交给 HTTP 引擎 |
| RTMP / RTSP 等流 | 交给 ffmpeg 抓取，与直播录制共用 |
| ed2k | **自行用 Rust 实现协议**（不依赖现成库）：解析 `ed2k://` 文件链接（名称、大小、MD4 哈希） 链接；连接 eD2k 服务器查找来源，再与来源直连按块下载（9.28 MB 分块，逐块 MD4 校验，AICH 可选）；Kad 网络作为后续项。参考 eMule / aMule 的协议文档与源码、Gopeed 的下载器架构（任务/分块/来源管理）；协议实现按文件拆成独立模块并配测试（用本地模拟服务器验证握手、来源查询、分块传输和校验）。风险：公开的 eD2k 服务器已大幅减少，可用性取决于用户配置的服务器列表和 Kad，不内置任何资源索引或搜索；先做“有链接就能下”，不做搜索 |
| BT / 磁力 | 内置 librqbit（Rust，Apache-2.0）：DHT、PEX、UPnP，Tracker 列表**定期从网上的开源列表自动更新**（默认源为 ngosang/trackerslist 的 best 列表，通过 jsDelivr / GitHub 镜像地址获取，更新间隔默认 7 天，可改；可手动立即更新、增删自定义源和自己的 Tracker，更新失败保留旧列表并提示，列表去重并只接受 http/https/udp 地址）；不内置任何资源索引或搜索 |

## 五、阶段 4：下载引擎打磨（0.8.0）

已完成，说明见 [download-engine.md](download-engine.md)。

- 普通文件的哈希校验（MD5 / SHA-256 / SHA-512），不匹配则报错并重下。
- 分片数 1–64 可调；按域名记住“不支持分片”或“连接数受限”；失败自动降级。
- 连接复用、重试退避；同一文件填多个镜像地址。
- 边下边播：MP4 / TS 下载中可在内置播放器预览。
- 完成后动作：关机、休眠、退出、运行命令。
- 核实并补全 HTTP / SOCKS5 代理，可按站点设置。

## 六、阶段 5：扩展性与远程（视反馈再定）

- 自定义站点规则增强；JS 脚本扩展需要先设计沙箱，再决定是否做。
- 云盘 / 离线下载（PikPak、115 等）：取决于需求和接口稳定性。

## 七、不做的

- **网盘直链解析**（百度网盘等）：解析存在服务条款和法律风险。只支持用户自己提供的直链加自定义请求头。
- **Android / iOS 原生 App**：手机网页和快捷指令已覆盖主要场景，原生应用的维护成本很高。

## 八、需要确认的默认值

这些是规划时先采用的默认值，随时可以改：

1. BT 内置：是（安装包约增加 5–10 MB）。
2. 手机上传单文件上限：默认 4 GB，设置里可改，0 为不限制。
3. 扩展接管下载：默认关闭。
4. 发布节奏：按阶段分版本发布。
