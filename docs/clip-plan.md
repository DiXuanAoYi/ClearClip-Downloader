# 剪辑功能规划：参考 AI 剪辑软件的 10 项新能力

状态：**A – E 期已做完，只有“人像抠图”和“人声分离”两项评估后暂缓**（见文末“实现状态”）。下面的规划按当时的设想写，和实际实现有出入的地方以 [video-edit.md](video-edit.md) 为准。

本文只说“工具箱 → 剪辑”要加什么。现有功能见 [video-edit.md](video-edit.md)（多轨时间线、转场、文字、叠加、区域追踪、实时预览等），AI 的基础（语音转文字、LLM 翻译 / 摘要）见 [library-and-tools.md](library-and-tools.md)。

## 一、参考了谁，缺什么

| 软件 | 它的 AI / 智能功能里，用户最常用的 |
|---|---|
| 剪映 / CapCut | 文稿剪辑（改字幕就是剪视频）、智能剪口播（去静音和语气词）、智能字幕与动态字幕、卡点、智能抠像、智能裁切画幅、精彩片段 |
| Descript、Adobe Premiere Pro | 基于文字稿的剪辑、删除口头禅、Auto Reframe、场景编辑检测、Enhance Speech（语音增强） |
| DaVinci Resolve 20 | Voice Isolation（人声分离）、Magic Mask（智能蒙版）、IntelliCut / IntelliScript（按静音和脚本自动粗剪）、Smart Reframe、动画字幕 |
| Opus Clip、Vizard 一类“长转短”工具 | 从长视频里自动挑精彩片段，竖屏、加字幕、给分数 |
| Filmora、Kapwing、VEED | 关键帧、绿幕、字幕模板、一键去背景噪音 |

> 联网只查到了 [DaVinci Resolve 20 的发布资料](https://www.blackmagicdesign.com/media/partial/release/20250404-02)（人声分离、智能蒙版、Smart Reframe、AI 动画字幕、静音 / 对白自动整理等）可作依据；剪映的功能我没有找到可靠的官方清单，上面是按常见使用整理的，以你装的版本为准。

清影现在已经有：时间线剪辑、区域追踪（含“跟随聚焦”）、文字、字幕导入、语音转文字（whisper.cpp 或在线接口）、大模型翻译 / 摘要 / 章节、镜头切分（媒体库里）、防抖、降噪（视频）、LUT 调色。**缺的是把这些 AI 结果直接用在时间线上**：识别出来的字幕不能直接变成剪辑操作，静音和口头禅要手动一段段找，横屏转竖屏要手动画框，没有关键帧，没有抠像，没有节拍。

## 二、取舍原则

1. **全部在本机完成**，不上传素材。需要模型的功能，模型在“设置 → 组件”里按需下载（和 ffmpeg、yt-dlp 一样），不内置、不强制。
2. 尽量用 **ffmpeg 现有滤镜 + 清影已有的解码 / 追踪代码**；需要神经网络模型时，只选体积小、许可证宽松的（见各项说明）。
3. **AI 只给“建议”，落到时间线上是普通的片段 / 文字 / 标记**，用户能撤回、能手改，不做黑盒“一键成片”。
4. 隐私模式下不运行会写缓存或调用在线接口的步骤；在线接口只在用户已经在设置里配置了的情况下使用，且每次都说明会上传什么。
5. 先做收益大、风险小的，需要大模型文件或大改时间线结构的放后面。

## 三、10 项功能

编号不代表顺序，顺序见“分期”。工作量：小 ≈ 几天，中 ≈ 一两周，大 ≈ 两周以上。

### 1. 文稿剪辑（按文字稿剪视频）　参考：Descript、Premiere、剪映“文稿”

- **做什么**：选中时间线上的片段，点“生成文稿”，右侧出现带时间的文字稿；在文稿里选中一句话 / 一段，点删除，对应的画面和声音被剪掉（时间线上变成分割 + 波纹删除）；点一个词，红线跳到它说话的位置。
- **怎么做**：用现有的语音转文字（whisper.cpp 或在线接口）。**需要词级时间戳**：whisper.cpp 加 `-ml 1`（或输出完整 JSON），在线接口用 `timestamp_granularities=word`（`verbose_json`）。把词合并成句，按词边界稍微外扩（前 0.05 秒、后 0.1 秒）避免咬字。文稿结果缓存在工程文件里，素材和入点 / 出点不变就复用。
- **限制**：识别有错字时只能“剪”不能改画面里的话；只处理主轨视频 / 音频片段；多人说话不分说话人（见备选）。
- **工作量**：大（要新增“文稿”面板，并让删除操作和现有分割、波纹删除、撤回打通）。

### 2. 一键去静音和口头禅　参考：剪映“智能剪口播”、DaVinci IntelliCut

- **做什么**：对选中的片段检测并列出“静音段”“语气词 / 口头禅（嗯、啊、那个、就是）”“重复的句子（可选）”，用户勾选后一次性剪掉，并可设置“保留多长的停顿”（比如留 0.2 秒）。
- **怎么做**：静音用 ffmpeg `silencedetect`（阈值和最短时长可调），不需要模型；口头禅依赖功能 1 的词级文稿，用可编辑的词表匹配（词表在设置里，用户可增减）。同时给时间线加上**音频波形**（`showwavespic` 生成一张图缓存，不逐帧解码），方便肉眼核对。
- **限制**：背景音乐很大时静音检测不准，可以先配合功能 6 的降噪；口头禅识别取决于识别质量。
- **工作量**：静音部分小，口头禅部分中（依赖 1）。

### 3. 智能字幕：自动识别 + 样式模板 + 逐字高亮　参考：剪映 / CapCut 动态字幕

- **做什么**：一键把语音转成字幕轨（现在只能导入已有的 SRT）；提供一组样式模板（描边、底条、关键词高亮、双语）；可选“逐字高亮 / 卡拉 OK”效果。
- **怎么做**：识别同功能 1；每条字幕就是现有的文字对象，样式模板是一组预设值；逐字高亮用 ASS 的 `\k` 标签或多层 `drawtext` 分段着色，导出时烧录（实时画面里近似）。双语复用现有的 LLM 翻译。
- **限制**：现在“文字”是单一样式静态文字，要先在数据结构里加“按词分段着色”；ASS 的复杂特效不追求，只做逐字高亮和淡入淡出两种动画。
- **工作量**：中。

### 4. 场景检测与自动分割　参考：Premiere“场景编辑检测”、剪映“场景分割”

- **做什么**：选中一个很长的片段（比如整场直播录像、合集），点“按场景分割”，在镜头切换处自动分成多个片段，可以调灵敏度，预览每个切点；随后逐段保留或删除。
- **怎么做**：媒体库里已经有基于 `select='gt(scene,…)'` 的镜头检测，抽出来共用；检测结果展示为时间线上的候选标记，确认后批量执行分割。
- **限制**：渐变、闪光多的素材会误判，所以先标记、再确认，不直接动时间线。
- **工作量**：小。

### 5. 一键重构画幅（智能裁切）　参考：Premiere Auto Reframe、DaVinci Smart Reframe、剪映智能裁切

- **做什么**：选中片段，选目标比例（9:16、1:1、4:5、16:9），程序自动找到画面里的主要运动物体，并让取景框整段跟着它走，生成一条可再调整的“跟随聚焦”区域。
- **怎么做**：现有的“区域”已经能做到：感知运动物体 → 追踪 → 跟随聚焦 + “按成片比例取景”。这一项是把它**串成一步**：自动选运动量最大的候选框，整段追踪，镜头平滑给默认值；多个镜头（配合功能 4）按镜头分别处理。找不到物体时退回居中裁切并提示。
- **限制**：不认识“人 / 脸”，只认运动物体；静止的采访镜头会居中裁切。想认人脸要等备选里的人脸检测模型。
- **工作量**：小到中（主要是串流程和多镜头处理）。

### 6. 人声增强与降噪　参考：DaVinci Voice Isolation、Adobe Enhance Speech、剪映“人声分离 / 降噪”

- **做什么**：片段的“音频”标签里加：背景降噪（轻 / 中 / 强）、人声增强（压低低频噪声、提亮人声、轻度压缩）、可选的“人声分离”（只留人声）。
- **怎么做**：降噪用 ffmpeg `arnndn`（RNNoise，模型文件很小，BSD 许可）或 `afftdn`（不需要模型，效果弱一些）；人声增强是 `highpass` + `equalizer` + `acompressor` 的预设组合；人声分离效果好的模型（Demucs 一类）体积大、速度慢，只作为**可选组件**，第一版不做，先把前两项做好。
- **限制**：精简版 ffmpeg 可能没有 `arnndn`，缺什么导出前说明什么（沿用现在的做法）；实时画面听不到处理效果，要“试听 15 秒”。
- **工作量**：小（降噪 + 增强），人声分离另算（大）。

### 7. 精彩片段提取（长转短）　参考：Opus Clip、Vizard、剪映“精彩片段”

- **做什么**：对一个长视频，给出若干候选片段（15–90 秒），每个有标题、分数和理由；选中后加到时间线（可一键竖屏 + 字幕）。
- **怎么做**：不靠视频理解模型，用**可解释的信号**打分：文稿（功能 1）交给用户已配置的大模型挑“完整、有信息量、有钩子”的段落并给理由；本机算音量起伏、语速、场景变化作辅助分数；候选的起止点吸附到句子和镜头边界。没有配置大模型时只用本机信号，并说明准确度有限。
- **限制**：一定会有“选得不对”的情况，所以只做建议；在线大模型会收到文稿文字（不含视频），使用前明确提示。
- **工作量**：中（依赖 1、4）。

### 8. 关键帧动画与变速曲线　参考：剪映 / Filmora / Premiere

- **做什么**：叠加素材、文字、主轨片段的位置、大小、旋转、不透明度、音量可以在时间上打关键帧，带缓入缓出；主轨片段支持变速曲线（先慢后快、定格、倒放）。
- **怎么做**：数据结构里把这些固定值改成“值 + 可选关键帧列表”（旧工程自动兼容）；导出时用 ffmpeg 表达式（`overlay` 的 `x`/`y`、`rotate`、`volume` 的 `eval=frame`、`setpts` 分段）生成；实时画面用同一份插值计算。变速曲线分段处理，段内线性变速，音调保持。
- **限制**：这是对时间线数据结构影响最大的一项，要重新检查撤回、分割、复制、变速后关键帧的时间怎么跟着走；复杂曲线只做近似。
- **工作量**：大。

### 9. 抠像：色度键（绿幕）与人像抠图　参考：剪映“智能抠像”、Runway、Filmora

- **做什么**：叠加素材 / 主轨片段上加“抠像”：先做**绿幕 / 蓝幕**（选颜色、容差、边缘羽化、去溢色）；再做**人像抠图**（不用绿幕，把人从背景里分出来，叠到另一个背景上）。
- **怎么做**：色度键用 ffmpeg `chromakey` / `colorkey` + `despill`，不需要模型；人像抠图用体积小的分割模型（如 MODNet / RVM，几十 MB，Apache-2.0），在本机逐帧推理后输出灰度遮罩，**复用“区域”的遮罩合成管线**（`alphamerge` + `overlay`）。模型作为可选组件下载；需要在 Rust 里加推理运行时（ONNX Runtime 或 candle），这会增大安装包，所以放最后评估。
- **限制**：人像抠图在发丝、半透明、快速运动处会有边缘瑕疵，只给预览 + 手动修正遮罩的入口，不承诺影视级。
- **工作量**：色度键小；人像抠图大（新增推理运行时和模型管理）。

### 10. 节拍卡点与配乐适配　参考：剪映“卡点”

- **做什么**：为配乐分析节拍，在时间线上标出节拍点；选一组图片 / 片段，一键“按节拍排列”（每个片段的切换点对齐节拍）；配乐比视频长 / 短时自动选择结尾淡出或循环点。
- **怎么做**：解码音频成单声道 PCM，用能量 / 频谱通量做起拍检测（纯 Rust，几百行，不依赖模型），输出节拍时间和估计的 BPM；节拍作为时间线上的标记，吸附开关打开时拖片段会吸到节拍上。
- **限制**：节奏不清晰的音乐（古典、环境音）结果差，会提示置信度低；不做变速适配节拍。
- **工作量**：中。

## 四、分期

| 期 | 内容 | 为什么这样排 |
|---|---|---|
| A 打底 | **4 场景分割**、**2 里的静音检测 + 波形**、**6 里的降噪与人声增强（不含人声分离）**、**5 一键重构画幅** | 都能直接用 ffmpeg 或现有代码，不需要新模型，也不动时间线数据结构，收益立刻能看到 |
| B 文字驱动 | **1 文稿剪辑**、**2 里的口头禅**、**3 智能字幕** | 共用“词级文稿”这一个基础，先把它做稳，再在上面做三件事 |
| C 数据结构 | **8 关键帧与变速曲线** | 对工程文件和撤回的影响最大，单独一期，做完整做回归测试 |
| D 画面与节奏 | **9 色度键**、**10 节拍卡点** | 依赖较少；人像抠图推迟到有明确需求时 |

每期的收尾：更新 [video-edit.md](video-edit.md)、CHANGELOG、`docs/roadmap.md`，并补端到端测试（沿用现有的 `e2e_tests.rs` 那一套：造素材、跑 ffmpeg、检查结果）。

## 五、备选（这次没选，将来可能加）

- 画质增强：超分辨率（Real-ESRGAN）、补帧（`minterpolate` 或 RIFE），耗时长，适合单独做“视频增强”工具而不是剪辑。
- 配音：本机语音合成（TTS）、视频翻译配音（识别 → 翻译 → 合成 → 对口型），对口型不现实。
- 说话人分离（给文稿标记谁在说话）、人脸检测（让重构画幅认人）。
- 特效 / 滤镜 / 贴纸 / 文字动画模板库：需要素材版权，先考虑让用户导入自己的 `.cube` 和 PNG / GIF 贴纸（已经支持）。
- 多机位同步（按声音对齐）、代理剪辑（高分辨率素材）。

## 六、需要你确认的点

1. 顺序：同意先做 A（不用模型）再做 B（文稿驱动）吗？还是想先要关键帧（8）？
2. **模型下载**：RNNoise（降噪，约 1 MB 级）可以接受“设置 → 组件”里按需下载吗？人像抠图 / 人声分离的模型更大（几十到几百 MB），放最后，接受吗？
3. **在线大模型**：功能 7（精彩片段）会把**文稿文字**发给你已配置的大模型接口，默认关闭、每次确认，可以吗？
4. 现有的 whisper.cpp 需要用户自己填路径；要不要顺便做成“组件”一键安装（词级文稿依赖它，体验差距很大）？

## 七、响度标准化里加“高级混响”的评估

另一个想法：在“工具箱 → 视频与音频 → 响度标准化”里加参考 PotPlayer 的高级混响。写在这里是为了和上面的音频功能（6）放在一起排期。

**可行。** 用 ffmpeg 就能做，视频画面照样不重新编码，只重新编码音频。

- **PotPlayer 的混响**（据我所知基于 DirectSound 的 Waves Reverb，参数是输入增益、混响混合、混响时间、高频衰减比，另有“大厅、浴室”等预设）是**播放时实时处理**；清影的工具箱是**处理成新文件**，所以是“离线加混响并导出”，不是播放器里的实时开关。
- **参数**：预设（小房间 / 浴室 / 客厅 / 教室 / 大厅 / 教堂 / 板式）+ 高级项：混响混合（干湿比，dB）、混响时间（RT60，毫秒）、高频衰减比、预延迟、输入增益。
- **实现**：ffmpeg 的 `afir`（卷积混响）配一段按参数**合成**的脉冲响应——白噪声乘指数衰减包络（衰减速度由混响时间决定）、低通模拟高频衰减、左右声道用不同噪声保证立体感，所以不需要附带任何脉冲响应文件；`aecho` 只做“简易回声”备用档。混响放在响度标准化**之前**，这样最终响度才是用户设的目标，也不会因为混响加了能量而削波（`loudnorm` 带真峰值限制）。
- **限制**：`afir` 在精简版 ffmpeg 里可能没有（缺了就在界面上说明并退回 `aecho`）；长素材的卷积耗 CPU，会比纯响度标准化慢一些；5.1 声道先降为立体声处理；不能实时试听，所以提供“试听前 15 秒”。
- **建议的位置**：不建议直接塞进“响度标准化”的面板——它是**音效**，不是标准化，参数有七八个，和那一个“目标 LUFS”放一起会让面板变得混乱，而且“只想加混响、不想动响度”也是合理需求。更好的做法是在同一组“视频与音频”里新增一项“音效 / 混响”，里面有一个勾选项“处理完顺便标准化响度到 N LUFS”，复用同一套处理，这样两种用法都顺手。后面还可以把 6 里的人声增强、降噪放进同一项，成为“音频效果”。
- **工作量**：小到中（预设 + 合成脉冲 + 面板 + 试听 + 测试）。

## 八、实现状态

| 项 | 状态 | 与规划的差别 |
|---|---|---|
| 1 文稿剪辑 | 已做 | 词级时间取决于识别引擎；接口只给整句时间时，词是按字数摊出来的；中日文的词时间比较粗 |
| 2 去静音和口头禅 | 已做 | 口头禅词表可改，误删由用户确认 |

### 为什么暂缓人像抠图和人声分离

两项都需要**神经网络推理运行时**加**模型文件**，在这个仓库里目前都没有：

- **运行时**：Rust 里要加 ONNX Runtime（`ort`）或 candle。ONNX Runtime 的动态库每个平台几十 MB，三个平台 + ARM 变体都要打进安装包 / 用 CI 分别处理；candle 体积小一些，但 MODNet / RVM / Demucs 的网络结构要自己用它重写并核对数值，工作量不小。
- **模型**：MODNet / RVM（几十 MB）、Demucs 一类（几百 MB）。要做成“设置 → 组件”里按需下载，需要稳定的下载地址、校验值和许可证核对。这次的开发环境无法访问这些地址，**写出来的下载和推理代码无法实际跑一遍**，我不想交付一段没有验证过的“功能”。
- **效果预期**：人像抠图在发丝、半透明、快速运动处有瑕疵，需要配套的遮罩手动修正入口；人声分离在 CPU 上很慢，需要进度、取消和缓存。

目前的替代：绿幕素材用“抠像”；想只处理人物所在的区域用“区域”（遮挡 / 局部调色 / 跟随聚焦）；想压背景噪音用“降噪 / 人声增强”。如果之后要做，建议先单独立项做“组件管理 + 推理运行时”，再接这两项。
