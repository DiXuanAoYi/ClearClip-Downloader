现状

当前 1.8.1 的“编辑术语库”，用假数据截的图。

1术语只有一层平铺的表格，“文件 › 打开文件”这种从属关系没法表达，菜单、设置项多了就分不清哪个“打开”是哪个菜单下的。
2每个格子都是带边框的输入框，几十行时满屏方框，看不清内容；“删”是红字挤在行尾。
3名称、语言、文件夹、网站四项占了半个对话框，术语表只剩 340 像素高。

术语分层的规则

结构每条术语都可以有下级，最多 6 层。上级本身也是一条术语，照样有自己的译文（“文件 = File”）。以前的术语库就是全部在第一层，打开后不用改。
翻译时命中“打开文件”时，把它的路径一起交给模型：界面 › 文件 › 打开文件 = Interface › File › Open File，上级的说明也带上（“软件界面的菜单和按钮”）。同一个原文在不同上级下可以有不同译法，按出现的上下文挑最接近的那条。
只作分组上级只想用来归类、不想当术语用：在 ⋯ 里勾“只作分组”，这一行显示成灰色小标题，不参与翻译，下级照常用。
编辑行内直接改，平时没有框，点进去才显示输入框。Enter 在下面加同级，Tab 变成上一条的下级，Shift+Tab 升一层，Alt+↑↓ 上下移，←→ 收起展开；也可以拖行首的点。底栏一直显示当前这条的完整路径和译文路径。
删除没有下级的直接删；有下级的问一次：只删这一条（下级升一层）或连同下级一起删。保存前都能 Ctrl+Z 撤回。
CSV导出多一列“上级路径”，如 界面/文件；导入时有这一列就还原层级，没有就都放在第一层。和沉浸式翻译互相导入导出时，多出的这一列对方会忽略，不影响使用。
搜索原文、译文、说明都能搜；命中的连同上级一起显示（上级变灰），清空后回到原来的展开状态。
外观沿用现有主题，亮色和暗色都适配：层级用缩进加细竖线，每一层一种底色（第一层最深，越往下越浅，第三层以下同一种），行与行之间留 3 像素空隙；有下级的行首有展开箭头，收起时显示“N 条下级”；第一层的分组加粗；当前行浅橙底；保存按钮用深一档的橙。对话框加宽到 960，基本信息压成一行，术语区占满剩下的高度。
